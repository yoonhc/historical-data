# BTCUSDT 데이터 플랫폼 진행 기록 — 2026-09-22

BTCUSDT 현물·USDT 무기한 선물의 독립 데이터 플랫폼을 구축하고, 3년치 데이터 확보와
품질 검증, 자동 갱신, 기존 Freqtrade Docker로의 데이터 전달을 완료했다. 알려진 과거
결측과 OI 해석의 불확실성은 그대로 기록하고 있다. 이 프로젝트의 범위는 데이터 수집·보관·
검증·재현 가능한 전달이며, 전략 개발과 수익성 연구는 별도로 진행한다.

이 문서는 **`a0134cc`까지의 구현과 2026-09-22에 보존한 검증 기록**을 정리한 기준점이다.
아래 수치는 각 보고서의 확인 시점에 해당한다. 문서 작성 과정에서 테스트·수집·백테스트를
다시 실행한 결과는 아니며, 실시간 운영 상태나 이후 누적 관측량을 나타내지 않는다.
이후 큰 단계가 끝나면 새 날짜의 문서를 추가하고, 이 기록의 기준 시점은 유지한다.

**구조와 주요 결정**은 다음과 같다.

```text
Binance 공개 데이터
  → data/raw: 원본·해시·수집 근거
  → data/canonical: 표준 Parquet와 불변 revision
  → data/snapshots: 입력 버전을 고정한 manifest
  → 플랫폼별 어댑터
  → data/exports: Freqtrade 등의 소비 형식

state/catalog.sqlite: 파일·활성 revision·품질 문제·수집 실행 이력
```

- `packages/marketdata`와 `packages/marketdata_freqtrade`를 분리했다. 수집 코어에는
  Freqtrade 의존성이 없으며, 다른 소비 플랫폼은 표준 데이터 위에 어댑터를 추가한다.
  새로운 거래소의 원천 형식·수집 방식은 수집 계층에서 별도로 구현해야 한다.
- 원본과 수정 이력을 보존해 출처를 추적하고, 고정 스냅샷으로 같은 입력을 재사용한다.
  원천 수정본이 기존 값과 충돌하면 검토 후 명시적으로 채택한다. 기존 스냅샷은 유지한다.
- 표준 데이터는 UTC와 Decimal을 사용한다. 모든 기간은 시작 포함·끝 제외 `[start, end)`다.
  소비 도구에 필요한 형식 변환은 어댑터에서 수행한다.
- 누락 봉을 임의로 채우거나 격리된 OI를 정상값으로 바꾸지 않는다. archive/REST OI도
  별도 시계열로 유지해 값 일치와 시간·단위 검증을 구분한다.
- 자동 수집은 원본과 표준 데이터를 갱신한다. 스냅샷과 Freqtrade 출력은 명시적으로
  새로 생성하므로, 기존 연구 입력이 자동으로 바뀌지 않는다.

설계 근거와 저장 규칙은 [설계 문서](../data-platform-design.md)에 있다.

**남은 범위와 다음 우선순위**는 다음과 같다. 아래 순서는 제안이며 새 구현의 완료 기록이 아니다.

1. OI 관측을 계속 누적하고 날짜별 출처 일치·관측 공백·값 변경을 검토한다. 단위와 시간
   라벨 의미는 별도로 검증하며, 최초 존재만 확인한 표본에서 공개 지연을 확정하지 않는다.
2. 원본·표준 데이터·스냅샷과 일관된 카탈로그의 전체 백업 및 복원 검증을 자동화한다.
   현재 보존한 SQLite 백업과 절차 문서는 전체 데이터 백업의 완료를 의미하지 않는다.
3. 수집 실패·지연과 품질 보고서의 검토 항목을 외부 알림으로 연결한다. 현재는 로컬
   상태·로그·보고서로 확인한다.
4. 연구 요구가 구체화되면 aggTrade·orderbook depth 수집, 당시 알려진 데이터만 사용하는
   완전한 시점별 재구성, Freqtrade 실시간 데이터 연결의 우선순위를 정한다. 모두 미구현
   또는 미완료 범위이며, 현재 고정 과거 데이터 출력과 구분한다.

알려진 가격 2분 결측과 OI 격리·결측은 남아 있다. 복구 가능한 원천을 추가로 확보하면
검토하되, 보간이나 자동 승인으로 완전한 데이터처럼 만들지 않는다.
