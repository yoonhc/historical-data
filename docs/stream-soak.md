# aggTrade·depth 동시 수집 안정성 검증

두 수집기를 같은 저장소에서 함께 실행하면서 기존 OI 수집과의 공존, 재접속, 데이터 일관성과
자원 사용을 확인한다. 상시 서비스를 설치하는 명령은 아니다. 각 실행은 최대 1시간 후 종료한다.

```bash
# output은 새 디렉터리를 사용한다. 시장 데이터는 기존 --root 저장소에 보존한다.
.venv/bin/python scripts/run_stream_soak.py \
  --output reports/soak/RUN_NAME --seconds 3600 --rotate-seconds 900

# 종료한 실행을 감사한다. 실행 중에는 최종 판정을 만들지 않는다.
.venv/bin/python scripts/summarize_stream_soak.py --output reports/soak/RUN_NAME
```

aggTrade는 `--fresh-start`로 이번 검증 구간을 시작하고 이전 표본과의 미수집 경계를 기록한다.
두 스트림은 기본 15분마다 연결을 교체하며, depth는 30초마다 별도 REST 스냅샷을 대조하고
일치하면 알려진 호가 범위를 갱신한다. 범위가 좁아지는 경우에도 추가 대조를 요청한다.
aggTrade의 재접속 누락은 REST로 복구하고, depth 연결 교체 사이 공백은 그대로 남긴다.

`run.json`에는 명령·PID·시작/종료·종료 코드·실행 코드 해시를 남긴다. `telemetry.jsonl`에는
30초 간격의 프로세스 RSS·최대 RSS·누적 CPU, 수신 시각의 신선도와 연결·오류·복구 건수를
기록한다. `latest.json`으로 최근 관측을 확인한다. 메모리는 해당 Linux 프로세스의 값이며
호스트 전체 사용량과 구분한다. CPU 백분율은 논리 코어 하나를 기준으로 계산한다.
프로세스가 끝나기 직전의 샘플 간 변화는 별도로 관측하지 못할 수 있다.

기존 운영 상태는 시작·종료와 5분 간격으로 확인한다. OI 최신 시각과 실행 ID가 갱신되는지,
등록된 9개 데이터셋의 정상 상태가 유지되는지 기록한다. 이 시간 동안 실행되지 않은 일별
타이머의 동시 부하까지 검증한 것으로 보지는 않는다.

종료 후 검증 내용은 다음과 같다.

- aggTrade를 5분씩 읽어 ID 누락·충돌·역순을 검사하고, 조회 구간 사이 ID 연결도 확인한다.
- depth를 저장 순서대로 재생해 당시의 호가장·대조 결과·범위 갱신과 일치하는지 확인한다.
- depth의 원문 가격·수량·ID·시각이 표준 Parquet과 같은지 대조한다.
- REST 응답이 현재 호가장보다 오래된 경우에는 저장된 직전 증분으로 같은 업데이트 ID까지
  진행한 뒤 top-N을 추가 대조한다. 증분 이력은 최대 128개 이벤트·50,000개 가격 수준으로
  제한하며, 연결할 수 없거나 값이 다르면 미검증으로 남긴다.
- 수집기별 메모리·CPU 관측과 저장 파일 수·크기를 정리한다.

추가 대조는 당시 수집 결과를 수정하지 않는다. `verification_complete`는 실시간 대조의
완료 여부이며, `delayed_snapshot_checks`와 `all_snapshot_checks_verified`에 추가 검증
근거와 전체 대조 여부를 별도로 기록한다. 범위 갱신도 실시간으로 일치한 스냅샷만 사용한다.

`summary.json`은 정상 종료, 두 자료의 감사, depth 원문·독립 스냅샷 대조, 기존 운영 상태가
모두 충족될 때만 `passed=true`다. 초기화 대기나 계획된 연결 교체와 데이터 오류는 원래
보고서에 구분해 남긴다. 확인한 실행의 통과를 장기 무중단이나 모든 변동성 상황으로 일반화하지 않는다.

초기 검증에서는 고정된 스냅샷의 가격 범위 소진을 관측했다. 이 기록을 보존하고 검증된
스냅샷으로 범위를 갱신하는 정책을 추가했다.
[2026-09-23의 1시간 재검증 결과](../reports/baseline/stream-soak-2026-09-23/summary.md)에
실제 수집·복구 수량, 원문·독립 스냅샷 대조, 자원 사용과 백업 복원 근거를 보존했다.
