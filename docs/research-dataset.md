# 3년 연구 데이터셋

고정 수집 범위는 UTC **2023-09-22 00:00 ≤ 시각 < 2026-09-22 00:00**이며 총 1,096일입니다.
수집 코어와 연구 스냅샷은 Freqtrade와 독립적입니다. 이 단계에서는 과거 자료 확보·품질 보고서·
스냅샷을 만들고, 전략 개발과 Freqtrade의 전체 기간 내보내기는 다음 단계에서 진행합니다.

## 데이터와 해석

`configs/research-archive.toml`에는 현물·선물 거래 1분봉, 선물 마크·지수 1분봉,
확정 펀딩 이벤트, archive OI 5분 자료를 지정했습니다. REST OI는 제공 기간이 짧으므로
기존 5분 자동 수집에서 별도로 보존합니다. 현재 관측한 상품 메타데이터를 과거 규칙으로
간주하지 않습니다.

원본 아카이브와 체크섬을 함께 검증합니다. 현물 아카이브의 2025년부터 적용되는 마이크로초
시각 단위는 원천 어댑터에서 처리합니다. 월별 아카이브가 없으면 해당 월을 일별 요청으로
나누되, 원천에 없는 자료를 합성하지 않습니다. [Binance 공식 공개 데이터 안내](https://github.com/binance/binance-public-data)

OI의 0값 격리와 수정본 충돌은 자동 승인하지 않습니다. 격자와 파일 무결성 검사를 통과한
OI도 archive 기준 시각·수량 단위·공개 지연은 미확정입니다. 라벨을 자동으로 5분 이동하거나
REST OI와 하나의 시계열로 합치지 않습니다. 자세한 근거는 [기존 OI 검토](legacy-oi-review.md)를 봅니다.

## 수집과 재개

```bash
.venv/bin/marketdata backfill-set --config configs/research-archive.toml \
  --start 2023-09-22 --end 2026-09-22 \
  --report reports/research-backfill-2023_2026.json
```

기존에 완전한 자료는 건너뛰고 누락된 자료를 수집합니다. 월별 ZIP 또는 일별 ZIP·REST 배치마다
쓰기 잠금을 반납하고 잠시 대기하므로 정기 OI 작업이 사이에 실행될 수 있습니다. `update`와
`watch`는 쓰기 잠금을 최대 60초 기다립니다. 이미 완전하거나 격리된 날짜의 대기는 짧게 합니다.
단일 HTTP 요청의 지연·재시도 때문에 일시적인 수집 지연은 생길 수 있습니다.

중단 후 같은 명령을 실행하면 카탈로그의 실제 완전성을 검사하고 이어서 진행합니다.
`--report`는 배치가 끝날 때마다 원자적으로 갱신하므로 마지막 게시 위치와 실패 이유를 확인할 수
있습니다. 이 보고서는 해당 실행의 기록이고, 원천 작업 이력은 SQLite `jobs`에 남습니다.

한 데이터셋의 오류로 나머지 데이터셋의 수집을 중단하지 않습니다. 격리·충돌·누락이 남으면
종료 코드 2를 반환하며, 일부 자료의 게시 성공을 전체 구간의 완전성으로 표시하지 않습니다.
`--accept-revisions`가 필요한 수정본 검토는 별도 `repair` 작업으로 처리합니다.

## 품질 보고서와 스냅샷

```bash
# 읽기 전용 품질 보고서: 저장된 자료에서 월별 상태와 연속 구간을 계산
.venv/bin/python scripts/build_research_dataset.py

# 최소 7일 이상 연속된 구간을 고정 스냅샷으로 보존
.venv/bin/python scripts/build_research_dataset.py --snapshots
```

보고서는 각 데이터의 행 수·기대 행 수·누락 구간·격리 날짜와 월별 완전성을 기록합니다.
검사는 하루 단위로 파일 해시와 시각 열을 읽어 전체 3년 데이터를 메모리에 올리지 않습니다.
스냅샷 생성 시에도 같은 완전성 검사를 다시 수행하고 `allow_gaps=false`를 유지합니다.

| 연구 프로필 | 필요한 데이터 | 사용 구간 |
|---|---|---|
| `spot` | 현물 거래봉 | 완전한 현물 구간 |
| `price_funding` | 현물·선물 거래봉과 펀딩 | 마크·지수 가격을 요구하지 않는 통계 연구 구간 |
| `futures` | 선물 거래봉·마크·지수·펀딩 | 모든 입력이 함께 확보된 구간 |
| `core` | 위 현물·선물 자료 | 두 시장을 함께 연구할 수 있는 구간 |
| `core_with_archive_oi` | core와 archive OI | OI 누락·격리도 제외한 구간; 시각·단위 가정 검증 필요 |

`price_funding`은 통계 연구용 입력이며, 마크가격을 요구하는 선물 백테스트의 입력을 모두
포함하지는 않습니다. 해당 연구에는 `futures`나 `core` 프로필의 완전한 구간을 사용합니다.

자료별 누락과 격리를 합집합으로 제외한 뒤, 모든 입력의 시간 격자에 맞춘 연속 구간을 계산합니다.
짧은 구간도 보고서에는 남으며, `--min-snapshot-days`보다 짧으면 자동 스냅샷만 생략합니다.
기간의 시작 부분은 전략 지표의 준비 구간이 필요할 수 있으므로 전부 거래 평가 기간으로
사용할 수 있다고 가정하지 않습니다.

펀딩의 완전성은 API 조회 범위의 완전성입니다. 고정 8시간 간격이나 모든 정산 이벤트의 존재를
별도로 증명하지 않습니다. 모든 스냅샷은 `historical_assumption`이며, 과거 당시 실제 공개된
수정본 전체를 재구성한 자료는 아닙니다.

고정 검증 기록은 [연구 데이터셋 보고서](../reports/baseline/research-2023_2026/summary.md)를 봅니다.
시장 데이터·카탈로그는 Git에 포함하지 않으며, manifest와 해시는 데이터 백업을 대신하지 않습니다.
