# 작업용 checkpoint 정리 구현·격리 검증·운영 미리보기

2026-10-03. [보관 정책](../../../docs/restic-transition-and-retention.md)을 구현·시험하고,
23:38~23:39 KST 운영 미리보기를 완료했다. **운영 삭제 0건, 실제 회수 0바이트**다.
`apply_enabled=false`를 유지하며 정리 타이머를 설치하지 않았다. 기존 daily·restic·수집 예약,
원본·revision·기존 사본·시험 산출물·복구 키트를 보존했다. `forget`·`prune`은 실행하지 않았다.

## 구현

- `scripts.retire_checkpoints`에 plan/status와 명시적 전체 계획 ID를 받는 apply를 추가했다.
  최신 검증 사본 3개와 완료 후 72시간 미만의 합집합을 보호한다. 원본 데이터의 무기한 보존과
  백업 날짜별 보관은 분리하며, restic 지점 만료 기능은 추가하지 않았다.
- 현재 미해결 오류·미보관·검사 대기·복구 실패·설명 없는 사본 소실은 중단 사유다.
  복구된 과거 시도·실패 기록은 남기며 영구 차단 사유로 취급하지 않는다.
- maintenance → repository → 사본 부모 디렉터리 순으로 잠근다. 수동 재사용 백업·복원·검증,
  restic 보관/시험과 ArchiveReader가 같은 공유 잠금을 사용하고, 정리기는 배타 잠금을
  비차단으로 요청한다. 원본 collector writer/layout 잠금을 정리에 사용하지 않는다.
- 대상·inventory·진행 기록을 먼저 저장하고 상위 디렉터리까지 fsync한 뒤, 같은 파일시스템의
  전용 이동 영역으로 rename한다. 기록된 파일만 제거하며 중단 뒤 같은 계획으로 재개한다.
  원래 manifest/source_root와 archiver 기록을 수정하지 않는다. 날짜별 부모 디렉터리는 남긴다.
- 실제 적용 직전에 남길 사본의 파일 해시·카탈로그·pack 무결성을 검증한다. 기존 독립 복구
  receipt를 해시로 고정하고 실제 저장소의 지점·manifest와 대조하며, 54분 복구 절차를 반복하지 않는다.

## 검증

[검증 집계](validation.json)의 서로 다른 **434개 테스트는 최종적으로 모두 통과**했다.
최초 전체 실행은 433 통과·1 실패였다. 실패는 임시 개발 사본에 Git 이력이 없어 기존 시험
요약기의 `git rev-parse HEAD`가 실패한 것으로, 복원·조회·재백업 검사는 이미 통과한 상태였다.
임시 사본에 원래 커밋 정보를 연결한 후 관련 10개를 다시 실행해 모두 통과했다.
도중 Git HEAD 연결 전 재시도의 실패도 로그에 보존했다. 운영 저장소의 Git 이력은 변경하지 않았다.
보강 후 정리기 관련 5개도 별도 실행에서 통과했다. 실행별 결과는 `*-tests`/`*-focused`/
`trial-*` XML·텍스트에 보존하며, 재실행 횟수를 서로 다른 테스트 수에 중복 합산하지 않았다.
코드·테스트·새 미리보기 스크립트 Ruff와 diff 공백 검사를 통과했다.

주요 시험은 다음과 같다.

1. 별도 프로세스가 복원·검증·하드링크 재사용·조회·restic backup 입력을 읽는 동안 정리 잠금 거부.
   읽는 프로세스의 정상 종료·강제 종료 후 잠금 해제와 collector writer 독립성 확인.
2. 실제 restic 저장소에서 오래된 사본 2개 정리 → 남은 3개 무결성 확인 → 다음 daily의
   하드링크 백업 생성 → restic 저장·검사 → 재실행 processed=0, 기존 원문 해시·상태 이력 유지.
3. 이동 전·이동 직후·파일 일부 제거 후·최상위 폴더 제거 직전·제거 직후의 5곳에서
   `os._exit`로 프로세스를 종료. 예외 처리도 실행되지 않은 상태에서 동일 계획으로 재개.
4. 중단한 폴더에 예상 밖 파일을 추가하면 정리를 중단하고 그 파일 보존. 미해결 오류·잘못된
   UUID/저장소 ID·변경된 복구 증거·손상된 유지 사본·오래된 계획도 거부. 편입 전 사본 제외 확인.
5. 격리 저장소에서 snapshot 파일을 별도 보관 위치로 옮겨 유실을 재현.
   로컬 정리 기록과 관계없이 다음 archiver와 정리 미리보기 모두 유실 오류를 보고함.
6. 완료 처리된 로컬 사본을 원래 경로로 되돌려 재등장을 재현하면 재정리 대상으로 채택하지 않고
   중단함. 마지막 보강 후 이 상황과 다음 daily/restic 연결을 74.65초의 별도 시험에서 다시 통과했다.

전원 차단 시험이나 다른 호스트의 실제 정리 시험은 수행하지 않았다. 디렉터리 flock은 Linux의
협력적 잠금이므로 임의의 외부 `cp`·직접 조회 프로그램을 자동 감지하거나 강제 보호하는 것은 아니다.
