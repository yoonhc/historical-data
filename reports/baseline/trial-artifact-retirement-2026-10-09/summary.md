## 실제 적용과 보호 대상 확인

삭제 직전 동일 SSD UUID와 rw 마운트, 하위 마운트 부재, 네 경로의 전체 신원·목록을 대조했다.
관련 checkpoint 입력 부모 잠금을 배타·비차단으로 확보했고, 시험 저장소 잠금이 없는지 확인했다.
같은 사용자 프로세스의 파일 참조와 보이는 모든 UID의 명령 인자에서 후보 사용은 발견되지 않았다.
접근 제한 프로세스 3개는 사용자 systemd·인증 보조·음성 서비스로 확인했다. 이 관측은 모든 사용자와
비협력적 프로그램을 강제로 차단했다는 보장이 아니며, 시험 프로필 해제·협력적 잠금을 함께 사용했다.

전용 수동 코드에서 승인 목록만 처리했다. 파일별 신원을 제거 직전에 재확인하고, 디렉터리는 비었을
때만 제거했다. 128개 이하 단위의 의도·완료를 fsync한 진행 기록에 남겼으며 **6,565개 묶음이 모두
완료되고 미해결 묶음은 0개**다. 실제 적용은 첫 실행에 완료됐고 부분 실패·재실행은 없었다.
중간 중단 시에는 자동으로 다시 지우지 않고 기록과 남은 목록을 대조하도록 했다.

격리 시험은 보호된 형제 경로 유지, 예상 밖·변경 파일 보존, 외부 하드링크, 파일/부모 symlink,
경로 이탈, 중간 unlink 오류, 별도 프로세스의 공유 잠금 경합을 포함해 11건이 통과했다.
이는 이번 수동 실행의 검사이며 수집 코드나 기존 백업 도구를 수정한 것이 아니다.

실제 적용 전후에 다음을 확인했다.

- 운영 restic의 repository ID와 **14개 snapshot 전체 메타데이터 유지**.
- 유지 checkpoint·원본 프로젝트·공유 암호·원래 복구 receipt·검증 자료 존재와 해당 검증 해시 유지.
  원래 9/26 checkpoint 전체 검증과 운영 전체 읽기 검사 대조는 바로 앞 재확인 근거를 사용했다.
- 두 collector supervisor와 Chrony의 **동일 PID·InvocationID·active 상태 유지**.
- 운영 설정 해시 유지. 허용한 시험 프로필 한 개만 해제.
- 자동 checkpoint 정리 서비스·타이머의 **mask 유지**, 기존 반복 승인 변경 없음.
- 복구 키트의 기존 파일·디렉터리 **2,933개 항목 유지**. 비밀 파일은 내용이나 해시를 기록하지 않았다.

복구 키트에는 승인된 안내 `TRIAL-CLEANUP.md`와 실제 완료 기록 `TRIAL-CLEANUP-20261009.json`만 추가했다.
두 추가 파일의 해시와 완료 기록의 내용도 대조했다. 원래 키트 코드·프로필·기록을 덮어쓰지 않았다.
기존 시험 고유 pilot snapshot ID와 고정 복제본 자체는 폐기됐다. 다음 복구 시험은 보존한 원래 사본
또는 명시적인 운영 snapshot ID에서 새 경로·프로필로 시작한다.
