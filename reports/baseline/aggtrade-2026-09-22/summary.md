# BTCUSDT 선물 aggTrade 수집·검증 기록

2026-09-22에 Binance BTCUSDT USD-M 선물의 REST·WebSocket 수집을 구현하고 실제 표본으로
검증했다. 원문과 출처·수신 시각을 보존하고, 작은 불변 Parquet 세그먼트로 저장한다.
기존 캔들·OI 수집과 별도로 동작한다. 사용법과 필드 의미는 [수집 문서](../../../docs/aggtrades.md)에 있다.

복구한 ID는 `3460992982–3460993264`의 283건과 `3460995172–3460995390`의 219건이다.
연결 교체 중 원래 WebSocket에 생긴 두 공백은 삭제하거나 감추지 않았다. 복구 자료는
REST 출처로 남겼다. 따라서 [출처 대조](source-parity.json)의 `equal=false`는 원래 두
출처의 ID 집합이 다르다는 의미다. `mismatched_ids`는 비어 있고, `rest_only_ids` 502개는
복구한 두 구간과 일치하며, `combined.valid=true`다. 이 비교 명령의 종료 코드 2는 예상 결과다.

캔들의 개별 체결 횟수와 aggTrade 이벤트 개수는 비교 대상에서 제외했다. 예를 들어 첫
1분봉에는 개별 체결 1,549회, aggTrade 645건이 있다. 표본의 가격·수량 일치를 모든 시장
상황의 동등성으로 일반화하지 않으며, 원천의 보험기금·ADL 제외 규칙도 유지한다.

## 저장량과 복원

3분 WebSocket 표본의 원문 gzip은 136,538바이트, Parquet은 360,628바이트로 합계
497,166바이트다. 각각 36개 파일이며 파일시스템 할당량은 합계 659,456바이트다.
REST 복구·재조회, SQLite, 백업·복원본은 이 수량에 포함하지 않았다. 짧은 표본으로
하루 저장량을 확정하지 않는다. 상세 수치는 [용량 보고서](capacity.json)에 있다.

이벤트 세그먼트를 포함한 새 로컬 백업은 10,639개 파일, 869,407,994바이트다.
catalog에는 이벤트 수집 5개, 세그먼트 56개가 들어 있으며 백업의 writer 잠금 시간은
약 0.063초였다. 별도 디렉터리로 복원한 뒤 과거 9,138건과 실시간 구간 7,035건,
합계 16,173건의 전체 행·조회 감사 결과가 원본과 같은지 확인했다. 기존 스냅샷 20개의
manifest도 일치하며, 원본과 복원본의 등록 파일 무결성 검사 각각 10,618건이 통과했다.
이벤트 테이블이 없던 이전 백업 10,487개 파일의 검증도 통과했다.

## 자동 검증과 운영 범위

전체 테스트 137개가 통과했다. 새 aggTrade 테스트는 26개이며, 같은 밀리초의 1,000건 초과
페이지 분할, 반복 조회, 중복·충돌·ID 누락, 조회 예산, 429 대기 상태, 원문 보존, 캔들 불일치
보고, 연결 교체·단절·복구 실패·프로세스 재시작, 파일 손상·백업 복원을 확인한다.
Ruff 검사·포맷과 `git diff --check`도 통과했다. 테스트 실행 결과와 소스 해시는
[validation.json](validation.json), [tests.xml](tests.xml)에 고정했다. 의존성은
`websockets>=17,<18`을 추가했고 검증 설치 버전은 17.1이다.

기존 운영 대상 9개의 상태는 모두 정상이었다. 기존 네 타이머와 Freqtrade 설정은 변경하지
않았다. 180초 표본은 종료했으며 aggTrade 상시 systemd 서비스를 추가·활성화하지 않았다.
현재 상태는 고정 보고서가 아닌 `marketdata status`와 `marketdata aggtrade-status`로 확인한다.

현재 제한과 후속 범위는 다음과 같다.

- BTCUSDT USD-M 선물만 지원한다. 현물·공개 아카이브·장기 aggTrade 백필·호가 depth는 미구현이다.
- REST 시간 조회는 최근 47시간 안의 최대 59분, 이벤트 조회는 최대 1시간·입력 1,000,000행이다.
- 재접속 공백은 최대 20페이지까지 REST 복구를 시도한다. 원천 제공 범위를 벗어나거나 복구에
  실패한 자료를 완전하다고 처리하지 않는다.
- 감사의 연속성은 관측된 첫 ID와 마지막 ID 사이에 대한 판정이다. 수집 시작·종료 경계의 모든
  체결 확보나 장기 무중단 운영을 증명하지 않는다.
- `received_at`은 프로그램의 recv 반환 후 시각이다. 네트워크 도착 시각이나 최초 공개 시각은 아니다.
- 이벤트 조회는 전용 CLI/Python 함수로 제공한다. 기존 `Store.read`·고정 스냅샷 API 및 Freqtrade
  체결/Orderflow 어댑터에는 아직 통합하지 않았다.

Git에는 검증 보고서만 남긴다. 원문·Parquet·SQLite·전체 백업 manifest는 로컬에 보존한다.
