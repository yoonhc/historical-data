일반 파일 450,212개·디렉터리 389,756개를 조사했다. 일반 파일의 논리 크기는 194.65 GB이며,

파일과 디렉터리의 할당 블록 계산과 일치했다. 현재 SSD 여유 공간은 약 678.40 GB다.
197.34 GB는 할당 블록 기준 예상이며, 실제 삭제 후 여유 공간 증가분과 구분한다.

원본 데이터·revision·운영 카탈로그, `marketdata-historical`의 모든 유지 사본,
**운영 `marketdata-restic`의 14개 지점 전체**, 복구 키트 전체, 공유 암호·실행 파일·보고서는 보존한다.

정리 후에는 시험 전용 `~/.config/marketdata/backup-host.toml` 한 개만 해제하고, 복구 키트에

기존 키트 파일·암호·옛 보고서·manifest의 `source_root`는 수정하지 않는다.

## 이번에 확인한 근거

1. **보존할 대응 자료가 남아 있다.** pilot의 9/26 snapshot은 원래 편입 전 checkpoint와,
   9/27 snapshot은 운영 snapshot `726fe603…`와 backup ID·manifest 바이트가 일치한다.
   독립 시험 복제본의 7개 snapshot은 운영 저장소의 같은 ID·내용 트리·전체 메타데이터와 일치한다.
   정확한 ID·경로·해시는 [조회 결과](probe.json)와 새 계획에 고정했다.
2. **원래 9/26 사본을 현재 다시 검증했다.** [결과](retained-checkpoint-verification.json)는
   33,586개 파일·8,710,460,459바이트의 해시·카탈로그·묶음 검증 성공이며 약 59.75초다.
   197 GB의 시험 payload 전체를 다시 읽거나 54분 복구 절차를 반복한 것은 아니다.
3. **기존 전체 읽기 검사와 현재 지점을 대조했다.** 10/9 14:50:55 KST에 끝난 운영
   `check --read-data` 성공 receipt의 실제 파일·해시와 오류 0건을 확인했다.
   해당 검사에 포함된 14개 snapshot 집합이 현재 운영 집합과 같다.
   이번 재확인에서 새 restic 전체 읽기 검사·전체 복원을 실행했다고 주장하지 않는다.
4. **기존 증거가 보존돼 있다.** `historical_data/reports/`의 압축 manifest 8개·restore receipt
   4개에 대해 압축·해제 해시와 후보 경로의 현재 원문을 대조했다. 원래 복구 시험 보고서와
   자동 정리가 참조하는 복구 receipt의 해시도 그대로다.
5. **목록 변화는 설명된다.** 기존 12개 추출·복원·재백업 하위 트리의 전체 메타데이터 목록은
   그대로다. 네 상위 트리까지 비교하면 pilot `locks`와 복제본 `repository/locks` 두 빈 폴더의
   mtime·ctime만 바뀌었다. 이번 restic 조회의 잠금 생성·정리 시각과 일치하며 잠금 파일은 0개다.
   [전체 차이](comparison.json)를 남겼다. 후보 payload 전체의 현재 내용 해시를 재검사한 결과와는
   구분한다.

옛 계획에서 먼저 확인하려던 **10/6 첫 예약 checkpoint 정리는 이미 완료됐다.** 실제 run은

## 사용 여부·한계·다음 단계

실제 호스트의 백업 SSD UUID·rw 마운트와 후보 root inode가 기존 기록과 일치했다. 같은 사용자
프로세스 148개를 조회한 표본에서는 후보 cwd·fd·매핑 참조가 없었다. PID 1201·1216·207240의
접근 제한과 다른 사용자·관측 이후 새 작업은 미확인 범위다. 이 표본을 배타 사용 보증으로
해석하지 않으며, 실제 적용 직전 잠금과 사용 여부를 다시 확인한다.

신규 시스템 수집 유닛·`/etc/marketdata`까지 포함한 설정 해시를 고정했고 계획 작성까지 변화가
없었다. 두 수집 supervisor와 Chrony는 실행 중이었으며, 자동 정리 서비스·타이머는 모두
`/dev/null` mask 그대로다. 이 작업은 서비스·시각·정리 승인 파일을 변경하지 않았다.
일반 파일 조사 중 생길 수 있는 접근 시각, restic 읽기 명령의 일시 잠금은 조회의 부수 효과다.

시험 저장소를 제거하면 그 저장소 고유 pilot snapshot ID와 당시 고정 복제 상태는 사라진다.
동일한 원래 checkpoint 내용은 위 대응 자료에 남지만, 향후 시험은 명시적인 운영 snapshot과
새 작업 경로·프로필을 사용한다. 기존 시험의 물리 상태를 그대로 다시 여는 계약은 종료된다.

**다음 행동은 이 새 계획의 네 경로 삭제·시험 프로필 해제·키트 안내 추가에 대한 별도 수동 승인이다.**
10/5 계획은 `deletion_authorized=false`였고, 현재 가능 여부 확인을 실제 삭제 승인으로 확대하지
않았다. 승인 이후에도 직전 신원·목록·잠금 대조와 부분 삭제 기록을 포함한 위 수동 절차를 따른다.
공통 정리 엔진이나 반복 삭제 권한은 추가하지 않았다.
