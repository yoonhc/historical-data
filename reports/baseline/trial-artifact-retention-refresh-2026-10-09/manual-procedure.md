# T06 수동 적용 범위와 중단 기준

이 문서는 삭제 없는 재확인 계획의 실행 조건이다. 이번 작업에서는 삭제 실행기를 만들거나 실행하지
않았다. 최신 `plan.json`의 네 후보와 파일 목록, 시험 프로필 한 개, 키트에 추가할 안내·완료 기록만
수동 적용 대상으로 제시한다. 실제 삭제는 별도 승인 후 수행한다.

1. 승인한 전체 계획 ID와 입력 해시를 확인한다. 동일 SSD UUID와 후보의 실제 경로·inode·소유권,
   하위 마운트 부재, 일반 파일·디렉터리 목록과 링크 수를 직전에 재대조한다. 새 파일이나 설명되지
   않는 변화가 있으면 중단한다. restic 읽기 조회가 만든 빈 `locks` 폴더의 시각 변화도 임의로 무시하지
   않고 해당 조회와 연결해 기록한다.
2. 보존 사본·운영 snapshot·기존 전체 읽기 검사·복구 receipt를 확인하고, 시험 저장소를 사용하는
   작업과 restic 잠금이 없는지 확인한다. 같은 사용자 `/proc` 표본만으로 배타 사용을 보장하지 않는다.
   시험 프로필은 보존본과 바이트 대조 후 원래 설정 경로에서 해제하고, 프로젝트의 관련 checkpoint
   입력 부모 잠금은 배타·비차단으로 확보한다. 잠금 도메인이 되는 디렉터리를 먼저 제거하지 않는다.
   잠금을 사용하지 않는 직접 restic/복사 작업의 사용 여부가 불명확하면 적용하지 않는다.
3. 대상별 시작·진행·완료를 별도 파일에 내구성 있게 기록한다. 정확한 파일 목록만 순서대로 제거하고,
   각 디렉터리는 승인한 자식이 모두 제거된 뒤 비었음을 확인해 제거한다. 상위 경로 glob이나
   `rm -rf /mnt/backup/marketdata-*` 같은 삭제는 사용하지 않는다. 자동 checkpoint 정리기에 이 경로를
   전달하지 않는다. 중간 오류에서는 부분 삭제를 사실대로 기록하고 중단한다.
4. 재개할 때는 같은 계획·목록과 진행 기록을 대조한다. 아직 남은 파일의 신원을 다시 확인하고,
   이미 없어진 파일은 이전 삭제 기록으로 설명되는 경우에만 완료로 인정한다. 변경·미기록 삭제가
   있으면 원인을 확인한다. 제거한 시험 저장소의 고유 snapshot ID·고정 복제 상태 자체는 복구하지
   못한다. 이후 시험은 남긴 원래 checkpoint 또는 운영 snapshot에서 새 경로로 다시 시작한다.
5. 네 후보가 없어졌는지, 보호 경로와 운영 repository ID/snapshot이 유지되는지, 서비스 설정·자동
   정리 mask가 그대로인지 확인한다. SSD 여유 공간 전후 차이를 기록하되 동시 수집·쓰기나 열린
   파일 참조를 고려해 정확한 단독 회수량으로 단정하지 않는다.
6. 복구 키트의 기존 파일은 보존하고, 이전에 검토한 `recovery-kit-note.md`를 `TRIAL-CLEANUP.md`로
   추가하며 실제 완료 receipt를 함께 보관한다. 기존 보고서·manifest·source_root를 고치지 않는다.

기존 보고서·검증 자료·압축 manifest와 파일 목록은 `historical_data/reports/`에 남는다. 원본 시장
데이터·revision·모든 운영 restic 지점·유지 checkpoint·복구 키트·공유 암호는 삭제 대상이 아니다.
T04의 새로운 근거 백업·복원 작업은 별도 경로에서 진행하며 이번의 과거 네 경로에 포함하지 않는다.
수집·Chrony 재시작, RTC 변경, 자동 정리 재개, `forget`/`prune`은 이 수동 적용 범위에 없다.
