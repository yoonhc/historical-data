# aggTrade·depth 1시간 동시 수집 검증

BTCUSDT USD-M aggTrade와 100ms depth를 같은 저장소에서 1시간 수집했다. 기존 OI 작업도
계속 실행했다. 초기 시험에서 발견한 호가 범위 소진 문제를 수정한 뒤, 재검증은 정상 종료와
전체 자료 감사·독립 원천 대조·백업 복원 검사를 통과했다. 검증용 두 수집기는 종료했다.

- 실행: **2026-09-23 00:12:47~01:13:01 KST**
- 같은 시각의 UTC: 2026-09-22 15:12:47~16:13:01
- 각 수집기 요청 시간: 3,600초. 위 실행 구간에는 시작·종료 상태 확인도 포함한다.
- 설정: 15분마다 연결 교체, 5초마다 파일 확정, depth 독립 REST 대조 간격 30초
- 근거: [실행·소스 해시](run.json), [종합 결과](summary.json), [재실행 절차](../../../docs/stream-soak.md)

## 처음 발견한 문제와 수정

앞선 실행은 UTC 14:40:10~14:50:31의 진단용 기록으로 보존했다. 고정 스냅샷의 알려진
가격 범위가 소진된 사례 4회와 초기 스냅샷 연결 실패 1회가 있었고, 원인을 확인한 뒤 중단했다.
이 실행을 1시간 통과 결과에 포함하지 않았다. 재생은 당시 결과와 일치하지만 `valid=false`,
종합 판정도 `passed=false`다. [실패 기록](diagnostic/summary.json)

이후 같은 업데이트 ID에서 독립 REST 대조가 일치하면 스냅샷으로 알려진 범위를 갱신하도록
수정했다. 한쪽의 알려진 호가 수가 줄면 다음 정기 대조 이전에도 확인한다. 연결과 `pu` 연속성은
유지하며, 범위 소진·실제 누락·값 불일치가 발생하면 기존처럼 새 epoch로 재동기화한다.
이번 1시간은 이 수정이 적용된 실행이다. 모든 변동성 상황에서 소진을 방지한다는 보장은 아니다.

정책은 수집 보고서의 `refresh_from_checks`에 남긴다. 필드가 없는 이전 자료는 당시 규칙으로
재생하며, 기존 두 표본 총 2,074행의 재생 결과가 변경되지 않았음을 확인했다.
[이전 자료 호환성 검사](legacy-replay-check.json)

진단 실행 코드의 해시는 [당시 실행 기록](diagnostic/run.json)에 있다.
[소스 차이](diagnostic/capture-source.patch)는 기준 커밋 `1f256a4`에 적용하면 당시 6개 파일을
재구성한다. 재검증에서 실행한 6개 수집 소스는 최종 코드와 해시가 모두 같다.

## 기존 OI 작업과 자원

기존 9개 운영 데이터셋을 시작·종료와 5분 간격으로 총 14회 확인했고 모두 정상이었다.
REST OI 최신 라벨은 UTC 15:10에서 16:10으로 진행했다. 기존 15초 OI 관측 240회도 모두
완료·정상이었으며, 관측 간 최대 간격은 15.7224초, HTTP 요청 최대 시간은 약 0.791초였다.
[시작 상태](operations-before.json), [종료 상태](operations-after.json)

| 관측치 | aggTrade | depth |
|---|---:|---:|
| 프로세스 최대 RSS | 93.19 MiB | 101.30 MiB |
| 평균 CPU, 논리 코어 하나 기준 | 0.52% | 3.03% |
| 카탈로그 수신 기록의 최대 나이 | 6.030초 | 4.731초 |
| 설정된 지연 기준 초과 표본 | 0 / 119 | 0 / 119 |
| 원문 파일 | 702개, 2,041,501바이트 | 837개, 29,734,560바이트 |
| Parquet 세그먼트 | 702개, 6,159,986바이트 | 837개, 48,249,166바이트 |

30초 간격으로 121개 관측을 남겼고, 각 프로세스 메모리는 종료 전 120개 표본에서 읽었다.
수신 기록의 나이에는 파일 확정 간격과 재접속 시간이 포함된다. 호스트 전체 CPU나 네트워크
지연 측정값은 아니다. [관측 원본](telemetry.jsonl)

이 실행의 원문·Parquet은 합계 86,185,213바이트(약 82.19 MiB), 3,078개 파일이다.
aggTrade 자동 복구분은 포함하고, 별도 3분 REST 검증 자료·SQLite·이전 자료·백업은 제외한다.
파일시스템 할당량은 92,471,296바이트다. 1시간 표본을 일별 저장량의 보장으로 사용하지 않는다.
다만 현재 파일 확정 빈도를 그대로 하루로 늘리면 약 7.4만 개 파일이 되므로 상시 운영 전에는
파일 병합·보관 기간·용량 경보를 먼저 설계할 필요가 있다.

전체 감사는 약 74.44초, 최대 RSS 167,208 KiB로 수행했다. depth 재생은 세그먼트별로 읽고
원문 대조 캐시도 현재 세그먼트에 한정해 전체 수집 자료를 한꺼번에 메모리에 올리지 않는다.
[감사 프로세스 관측](audit-resource.txt)

## 자동 검사와 복원

전체 테스트 **168개**와 Ruff 검사·포맷·diff 공백 검사가 통과했다. 새 검사는 fresh start의
명시적 경계와 재접속 복구, 호가 범위 갱신·중복 감지·과거 정책 재생, 지연된 스냅샷의 일치와
불일치 판정을 포함한다. [테스트 결과](tests.xml), [소스·근거 해시](validation.json)

원본 등록 파일 무결성 14,440건이 통과했다. 새 백업은 14,461개 파일, 984,741,171바이트이며
카탈로그 고정 중 writer 잠금은 약 0.052초였다. 별도 경로로 복원한 뒤 depth 전체 재생,
aggTrade 12개 구간 감사, 기존 고정 스냅샷 20개의 manifest가 원본과 일치했다.
복원본 등록 파일 무결성 14,440건도 통과했다.

- 백업: `backups/stream-soak-2026-09-23`
- 복원본: `restore-checks/stream-soak-2026-09-23`
- 근거: [백업](backup.json), [복원](restore.json), [복원본 대조](restored-check.json), [원본 무결성](live-integrity.json)

백업·복원본은 원본과 같은 파일시스템에 있다. 외부 백업·정기 예약은 추가하지 않았다.
기존 수집 타이머와 Freqtrade 설정도 변경하지 않았다. 시장 데이터와 SQLite는 로컬에 보존하고,
Git에는 코드와 검토한 검증 근거만 남긴다.

## 적용 범위

이번 결과는 한 번의 1시간 동시 수집에 대한 근거다. 일별 타이머가 실행되지 않은 시간대이므로
그 작업까지 동시에 수행한 부하 시험은 아니다. 24시간 무중단, 네트워크 장기 장애, 디스크 고갈,
모든 변동성 상황이나 전체 가격 범위의 완전한 호가장을 보증하지 않는다. 거래소·로컬 시계
오차도 검증·보정하지 않았으므로 수신 시각 차이를 통신 지연으로 해석하지 않는다.

상시 수집 서비스, 장기 aggTrade 아카이브, 현물 스트림, 이벤트 고정 스냅샷과 Freqtrade
체결·호가 어댑터는 후속 범위다. 다음 우선순위는 파일 병합·보관 정책과 운영 경보를 정한 뒤,
장기 실행을 위한 수집 세션·재시작·검증 범위를 확장하는 것이다.
