# T02 — 전환 후 첫 24시간 관찰

**첫 24시간의 재시도·시각 관측·저장 점검을 완료했다.** 관찰 완료와 무손실 운영은 구분한다.
구버전의 시각 gate 지연, 전환 도구 문제로 길어진 수집 공백, 호가 범위 소진은 실제로 있었다.
새 runtime에서는 reference 지연 중 두 스트림이 각각 다음 child를 4번 시작했다.
운영 설정·서비스·Chrony·RTC·수집 요청·자동 정리 상태는 변경하지 않았다.

## 범위와 판단 기준

- 고정 구간: **2026-10-09 00:11:18 이상 ~ 10/10 00:11:18 미만 KST**, 정확히 86,400초.
  최종 부팅에서 준비를 통과하고 collector 서비스가 시작한 초를 기준으로 삼았다.
  전원을 켠 시각이나 첫 WS 행의 시각과는 다르다.
- boot ID `eb163bf2-6642-4336-b4d6-6cd58771b13d`.
  19:33 이전 `system-bootstrap-20261007-f85eb8321a19c1ee`, 이후
  `clock-evidence-policy-20261009-65296619a374c325`를 구분했다.
  **한 버전의 24시간 무중단 검증이 아니다.** 새 runtime의 이 구간 관측은 약 4시간 37분이다.
- 분석은 10/10 오전에 저장 기록으로 수행했다. 별도 현재 호스트 확인은 **09:53:38 KST**다.

  [전환 중단·보완·재개](../clock-runtime-deploy-2026-10-09/summary.md)는 재사용했다.
  같은 전수 재생·장애 주입·REST 다운로드를 다시 실행하지 않았다.

카탈로그 대조는 동일 내용 segment가 다른 collection에서 누락될 수 있는 T12 전체 해결도 아니다.

세 사건 모두 시장 전체 주문 소멸이나 reference 지연의 결과라고 단정하지 않으며 독립 원인 분석은 별도다.

### aggTrade 경계 보강

구간 안의 연속 WS collection **23개 경계, 합계 37,935개 ID**는 저장된 REST segment의
범위 합집합으로 전부 연결됐다. 경계의 실제 첫/마지막 WS 행과 REST 표본도 읽었다.
이는 이번 세션 경계의 카탈로그 연속성·선택 표본 대조이며, 전체 REST 내용의 새로운 전수 검증은 아니다.

첫 collection의 partial은 부팅 전 공백의 미복구 이력이며 소급 정상화하지 않았다.
그 별도 **264,069개 ID의 보강·백업 완료**는 [기존 T03 결과](../aggtrade-gap-repair-2026-10-09/backup-inclusion.md)를 유지한다.
19:23–19:33 전환 경계 4,031개도 기존 보강 결과와 맞았다. 당시 Depth 원문·WS 수신 시각까지 복원된 것은 아니다.

## 시각과 재시도

저장된 provider 관측 **16,493개**에서 거부 사유는 `reference_age`뿐이었다.
미래 reference(음수 age)는 **0개**, 최대 reference age는 **3,624.417초**였다.
최대 남은 보정량 **21.385ms**, 조건부 오차 상한 **164.849ms**로 기존 100ms/500ms 조건 안이었다.
같은 Chrony PID `1245`·invocation을 유지했고 journal에 시각 step은 없었다.
이 값은 남아 있는 표본의 범위이며 표본 사이·감시가 없는 공백의 UTC 정확도를 인증하지 않는다.

v1 감시의 실행 중 사유는 `provider_unready`뿐이며 내부 provider 사유는 reference_age였다.
관측된 wall/boottime 차이 변화의 최대 절댓값은 약 **75.74µs**였고 큰 시각 이동 사유는 없었다.
`finished` 기록의 `clock_usable=false`를 신규 시각 오류로 세지 않았다.
경고 표본 수·시작 재시도 횟수를 독립 장애 수로 해석하지 않았다.

### T11 적용 후에는 같은 상태에서 다음 child가 시작됨

두 스트림 각각 첫 시작 이후 **20:34·21:34·22:34·23:34의 다음 child 4회가 전부 stale 상태에서 허용**됐다.

aggTrade 약 1,632/851/1,112/2,661초였다. 엄격한 최초 준비를 생략한 것이 아니다.

같은 supervisor PID·run이 유지됐고 종료·15초 대기 중 감시가 이어졌다.
시각 artifact **126개**의 해시·chunk 연결·record 순서를 읽었다.
구간 안의 기록은 스트림별 **16,443행**, 저장 표본 간격 최대 **1.050초 미만**이었다.
양쪽 모두 current estimate 거부·raw start 거부·hard fault는 **0개**였고 과거 stale 이력은 유지됐다.

## 기존 업무와 발견된 후속

기존 업무의 엄격한 gate는 여전히 적용된다. 기록상 가장 긴 공통 waiter는
**reference_age 때문에 약 4,036.785초(67분 17초) 기다린 뒤 16:01:17에 해제**됐다.
이 시간을 모든 업무의 실제 중단 시간이나 원문 수집 중단 시간으로 확대하지 않는다.
업무별 시각 요구 분리는 기존 조건부 목록에 남겨 두며 이번에 정책을 바꾸지 않았다.

데이터 갱신용 `marketdata-daily.service`는 00:14에 8개 target을 완료했다.
12:23–12:27 실행 5회는 **10/8 UTC의 선물 trade/mark/index bars 및 OI archive 4종이 waiting_source**였다.
각 오류 배열은 비어 있고 다른 4개 target은 complete였다. exit 2 후 재시도했고
**12:28:50에 시작 제한에 도달**했다. 10/10 오전 카탈로그에서도 이 4개 target의 마지막 실행은 같은 미완료 상태다.

현재 원격 파일 공개 여부는 이번 읽기 전용 점검에서 새로 조회하지 않았다.
이를 계속 원격 미제공이라고 확정하거나 다운로드·DB 오류라고 바꾸어 해석하지 않는다.
**T13**으로 다음 daily(설정상 12:20 KST + 최대 5분 분산·시각 gate 대기)의 실제 결과를 확인한다.
필요하면 그때 원격 제공 여부와 기존 갱신 재실행 범위를 결정한다. 서비스 재시작·reset-failed는 하지 않았다.
이는 checkpoint 생성용 backup 및 restic과 다른 업무다.

현재 고정 계획의 파일 해시·원래 boot/closed/step 증거·새 supervisor와 child UID 1000을 확인했다.
기존 사용자 collector와 자동 checkpoint 정리 service/timer는 `/dev/null` mask를 유지했다.
새 시각 근거의 **10/10 13:10 이후 checkpoint → restic → 명시적 복원 조회(T04)**는 아직 이번 결과에 포함되지 않는다.

## 완료 범위와 보존

T02의 합의 범위인 첫 세션 확인 및 첫 24시간의 재시도·시각 이상·저장 관찰은 끝났다.
미해결 품질 이력은 지우지 않고 [TODO](../../../TODO.md)의 **T07·T13**으로 연결했다.
새 근거의 운영 백업·복원/기존 v1 로그 편입은 **T04**, 자동 삭제 시각 검사·재승인은 **T05**다.
연속 수집·업무별 시각 요구·미동기화 부팅·시간원 재검토는 기존 조건부 항목을 유지했다.

원본 journal·조회 당시 카탈로그·닫힌 시각 로그 사본은 Git 제외 경로
`reports/t02-first-24h-2026-10-10/`에 보존하고 입력 해시·집계·선택 원문은 이 폴더에 남겼다.
그 로컬 사본을 restic 편입·복원 완료라고 주장하지 않는다.
최초 관측 도구는 journalctl에 하이픈이 있는 boot ID를 전달해 journal 조회만 거부됐다.
현재 호스트 검사는 이미 통과한 상태였고, journalctl 입력을 32자리로 고쳐 별도 조회를 완료했다.
운영 설정이나 검증 조건을 바꾸어 통과시킨 것은 아니다.
