정확한 backup ID·대응 경로·snapshot ID·manifest SHA-256은 `plan.json`의 `replacement_sources`와
`cloned_snapshots_also_in_production`에 고정했다. 저장소 이름이나 날짜가 같다는 것만으로 중복으로 판단하지 않았다.

원래 9/26 checkpoint는 **33,586개 파일·8,710,460,459바이트의 해시, 카탈로그, 묶음 구성 검증을 통과**했다.
[검증 결과](retained-checkpoint-verification.json)의 최종 실행 시간은 약 44.51초다.
첫 실행도 검증 함수는 성공했지만 결과 기록에서 `datetime` 직렬화 오류가 났다.
[불완전한 최초 기록](retained-checkpoint-verification-incomplete.json.txt)을 보존하고,
프로젝트의 `json_bytes`로 먼저 직렬화한 뒤 출력하도록 보고서 스크립트를 고쳐 같은 사본만 재검사했다.
운영 프로그램을 바꾸거나 오류 기록을 정상 결과로 덮어쓰지 않았다.

운영 저장소의 기존 **10/5 14:10 KST `check --read-data` 성공**은 현재 9개 snapshot과 위 대응 지점들을
포함한다. 이번에는 그 근거와 현재 snapshot을 대조했고, 전체 restic 읽기 검사·전체 복구 시험을
새로 실행했다고 주장하지 않는다. 원래 9/26 사본의 추가 검증과도 다른 범위다.

시험 저장소를 실제 폐기하면 **그 저장소의 고유 pilot snapshot ID와 고정 복제본은 사라진다.**
같은 원래 checkpoint 내용은 위 대응 자료로 남지만, 당시 restic 저장소 자체의 상태를 다시 여는
방식의 재현은 종료한다. 향후 복구 시험은 운영 snapshot의 명시적 ID와 새 출력 경로를 사용한다.

설치된 백업·restic·checkpoint 서비스와 환경 파일에서는 이 프로필을 사용하지 않는 것을 확인했다.
암호 값을 포함하지 않는 원문을 `preserved-backup-host.toml`로 정확히 복사하고 0600으로 보관했다.
**실제 정리 승인 후 기존 설정 경로에서 이 파일 한 개를 해제**할 계획이며, 현재 원본은 그대로다.
다른 운영 프로필·공유 암호는 바꾸지 않는다. 이후 새 시험은 새 프로필·입력·목적지를 명시한다.

복구 키트의 기존 안내에는 10/3 시험 복제 경로가 역사적으로 기록돼 있다.
[추가할 안내](recovery-kit-note.md)를 준비했으며, 실제 정리 때 키트에 `TRIAL-CLEANUP.md`와 완료 기록을
추가한다. 기존 키트 파일을 수정하지 않고 **다음 복구에는 운영 저장소와 새 작업 프로필을 사용**하도록
명시한다. 이 안내도 아직 키트에는 설치하지 않았다.

## 사용 여부와 운영 범위

실제 호스트 UUID `d90aaf81-2358-411f-8022-4e1a3f7b0973`와 세 저장소의 ID를 대조했고,
후보 안의 하위 마운트·심볼릭 링크·특수 파일은 없었다. 조회 종료 후 시험 저장소의 restic 잠금 파일은
0개였다. 보이는 같은 사용자 프로세스 156개를 두 번 조사했을 때 후보 파일·cwd·매핑 참조도 0개였다.
`systemd`·`(sd-pam)`의 일부 접근 제한과 다른 사용자·관측 이후 시작한 작업의 한계는 유지한다.
단순 프로세스 표본을 배타 사용 보증으로 해석하지 않는다.

설정 조회와 계획 작성 사이 운영 설정 해시는 같았다. 동결된 자동 정리 배포본과 기존 서비스 설정은
변경하지 않았다. 자동 정리의 복구 증거 조건은 **운영 저장소의 snapshot과 기존 receipt**에 연결돼 있어,
이 시험용 복제 저장소를 계속 요구하지 않는다. receipt 해시와 해당 운영 지점도 다시 확인했다.

   172 GB 초기안이나 checkpoint 반복 승인을 확대 해석하지 않는다.
3. 직전에 마운트·파일 신원·목록·현재 보존 지점·무결성 근거·설정 참조를 재대조한다.
   새 파일·변경·진행 중인 복원 작업이 있으면 중단하고 계획을 재검토한다.
4. 시험 프로필을 보관·해제하고 관련 입력 부모의 협력적 잠금을 배타·비차단으로 확보하는 등
   새 시험 작업과의 충돌을 막는다. restic 잠금과 직접 실행한 작업도 확인한다.
   기존 checkpoint 정리기에 시험 저장소를 전달하지 않는다.
5. 별도로 검토한 수동 절차에서 정확한 파일 목록과 대상별 진행·중단 기록을 사용한다.
