## 현재 상태와 reader 점검

[로컬 상태](status.json)에서 daily는 정상 주기이고 미보관 사본·미해결 사본 오류·검사에
포함되지 않은 지점·active operation은 없다. 마지막 전체 읽기 검사는 운영 지점 8개를 포함한다.
이번에 전체 논리 검사·`check --read-data`·54분 독립 복구를 다시 실행한 것은 아니다.

[02:30:53 프로세스 표본](reader-snapshot.json)에서 조회 가능한 같은 사용자 프로세스 중
checkpoint에 열린 파일·작업 디렉터리 참조와 부모 디렉터리 잠금은 없었다. 프로젝트의 관련
Python 프로세스 두 개도 소스 반영 이후 시작했다. 전체 접근이 제한된 PID 1189·1201은
[이름·시작 시각 대조](restricted-process-names.json)에서 systemd와 `(sd-pam)`이었다.

이것은 현재 표본이며 다른 사용자의 프로세스·모든 외부 프로그램의 향후 읽기·Python 메모리의
내용까지 증명하지 않는다. **실제 적용 직전에 다시 확인**해야 한다. 어떤 프로세스도 종료하거나
재시작하지 않았다. [전후 표본](after-plan.json)에서 호가·aggTrade는 running, 연결·저장 오류 0,
호가는 synchronized=true·미재구성 0이었다. 새로운 24시간 품질 검사 결과로 집계하지 않는다.

## 남은 작업

1. 위 전체 계획 ID와 정확한 대상 목록에 한정한 수동 적용 승인.
2. 적용 직전 reader·외부 복사 확인, 현재 저장소 대조와 남길 3개 사본의 파일 해시·카탈로그·pack 검사.
3. 조건 통과 시 수동 적용하고 예상 회수량과 파일시스템 여유 공간의 관측 변화를 구분해 기록.
4. 정리 후 남은 사본·restic 지점과 다음 실제 daily·예약 restic 실행 확인.

새 사본·정책·코드 변경으로 계획 조건이 달라지면 중단하고 새 계획을 검토한다. 계획이 commit을
포함하므로 이번 증거는 파일로 보존하되 **추가 commit은 아직 하지 않았다**. commit 후 기존 계획을
그대로 적용하지 않는다. 자동 정리, restic 지점 만료·prune, 시험 산출물 정리와 원본 삭제는 이번
승인 범위에 포함하지 않는다. 원래 source_root·manifest를 수정하거나 실패 이력을 지우지 않았다.
