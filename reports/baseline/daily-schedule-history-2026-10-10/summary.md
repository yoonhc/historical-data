# Daily 예약과 waiting_source 누적 현황

2026-10-10 저장된 카탈로그와 실제 사용자 systemd journal을 읽기 전용으로 대조했다.
**9/23–10/10 정오 정기 실행 18일 모두 최초 실행을 포함한 5회 안에 전체 완료되지 않았다.**
오후·야간 추가 실행에서는 전체 완료 사례가 있으며, 이번 10/9 UTC 보강까지 반영한 현재 daily 보고서는 8개 target 모두 complete다.

## 현재 조회 시각과 재시도

- 달력 예약은 **UTC 03:20 = KST 12:20**, `RandomizedDelaySec=300`으로 최대 5분 분산한다.
  실제 시작은 시각 준비·잠금 등으로 더 늦어질 수 있다.
- `waiting_source`는 별도 시각에 수신하는 거래소 상태가 아니라, 자료 요청 시 HTTP 404를 받은 프로그램의 분류다.
- 미완료 종료 후 60초 뒤 재시도하며 10분 내 최대 5회 시작한다. **최초 1회 + 재시도 4회**다.
  처리 시간이 약 6초이므로 관측된 5회는 대략 4분 반에 집중됐다.
- 활성화 30초 후 실행과 Persistent 예약 따라잡기도 있다. 모든 실행을 정오 달력 예약으로 분류하지 않았다.

실효 설정과 원본 journal은 [호스트 조회](host-history.json), [journal JSONL](daily-journal.jsonl)에 보존했다.

| 항목 | 결과 |
|---|---:|
| 날짜 범위 | 2026-09-23–2026-10-10 KST |
| 정오 실행 묶음 | 18일 |
| 실제 update 실행 | 90회: 매일 5회 |
| 5회 안 전체 8개 target 완료 | **0일** |
| 같은 네 선물 자료 waiting_source | **90회 모두** |
| report 오류 배열의 오류 | 0건 |
| 실제 journal 종료 코드 2 | 90회 |
| 정오 재시도 후 시작 제한 도달 | 18일 모두 |

기다린 자료는 매번 전날 UTC의 **선물 trade bars·mark price bars·index price bars·OI archive**였다.
나머지 현물 bars·funding·현물/선물 metadata 4개 target은 해당 정오 실행에서 complete였다.
각 날짜의 처음/마지막 실행, sync run ID, 기다린 URL·날짜·coverage는 [카탈로그 집계](catalog-history.json)에 있다.
동일 시각의 서비스 시작 5개·exit 2 다섯 개·시작 제한 1개를 날짜별로 대조했다.
[journal과 카탈로그 대조](cross-check.json).

## 정오 재시도 밖의 성공

전체 8개 target을 함께 실행한 기록은 107회이며 그중 9회가 complete다.
9/22 초기 오후·야간 4회와 아래 추가 실행 5회다. 시작 시각 자체를 원격 파일 최초 공개 시각으로 해석하지 않는다.

| 추가 실행 시각 KST | 해당 실행의 결과 |
|---|---|
| 10/5 20:04 | 8개 complete, 10/4 UTC 자료 편입 |
| 10/7 23:31 | 8개 complete, 10/6 UTC 자료 편입 |
| 10/8 21:39 | 8개 complete, 10/7 UTC 자료 편입 |
| 10/9 00:14 | 8개 complete, 당시 최신 완료 UTC 날짜는 여전히 10/7 |
| 10/10 18:52 | 8개 complete, 10/9 UTC 자료 편입 |

9/23 15:11 추가 실행은 여전히 네 자료 waiting_source였고,
9/27 오전의 별도 실행에서는 현물까지 다섯 자료가 waiting_source였다. 오후에 실행하면 언제나 성공한다는 결과는 아니다.
8개 key가 동일한 started_at으로 기록된 묶음만 집계했고, 개별 REST OI 등 다른 업무는 제외했다.

## 누적 미완료와 현재 보유 상태

정오 전체 complete 실패가 자료의 영구 누적 누락을 뜻하지는 않는다.
그보다 이전 날짜 자료는 다음 실행에서 편입되는 패턴이었다.
예를 들어 10/9 정오에는 10/8 UTC가 없었지만 10/10 정오에 편입됐고, 그때는 새 대상 10/9 UTC가 남았다.
10/9 UTC는 오늘 18:52 추가 실행으로 채웠다.

현재 active 카탈로그에는 이번 관측에서 기다렸던 **9/22–10/9 UTC 18일 × 4종 = 72개 날짜 파티션**이 모두 있다.
각 날짜의 총 행 수는 4,608행이다. 이번 역사 집계는 카탈로그 대조이며 72개 파일 전체를 새로 전수 검증하지 않았다.
오늘 10/9 네 파일의 실제 해시·격자 대조는 [재실행 검증](../t13-daily-rerun-2026-10-10/summary.md)을 재사용했다.

정오 예약과 짧은 재시도는 이 관측 기간의 전날 선물 자료 제공 시점에 맞지 않았다.
이는 예약·재시도 정책을 검토할 근거이며, 현재 수집 코드의 파싱 실패나 checkpoint/restic 실패로 분류하지 않는다.
정확한 최초 공개 시각은 기존 조회 간격으로 확정할 수 없다. 이번에는 서비스·타이머·시각 조건·재시도 정책을 변경하지 않았다.
