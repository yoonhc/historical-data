# 2019년 이후 BTCUSDT 과거 확장 검증

2026-09-23 UTC에 실시간 수집을 유지하면서 공개 원천의 과거 자료를 추가했다.
Freqtrade와 독립된 수집·검증 작업이며 원문·표준 자료를 기간 제한 없이 보존한다.
기존 3년 연구 revision 6,588개와 전체 스냅샷 20개의 해시는 변경되지 않았다.

## 최종 범위

종료 경계는 모든 자료에 대해 **2026-09-22 00:00 UTC 미만**이다. 원천 시작 전 구간은
아래 누락 집계에서 제외했다. 이 표는 시간 격자·조회 범위의 검증이며 연구 수익성,
과거 당시의 공개 시각, OI 단위·라벨 의미의 검증은 아니다.

| 자료 | 실제 시작 (UTC) | 표준 행 수 | 남은 누락·격리 |
|---|---|---:|---|
| 현물 거래 1분봉 | 2019-01-01 00:00 | 4,058,129 | 4,111분 |
| USD-M 거래 1분봉 | 2019-09-08 17:57 | 3,701,162 | 1분 |
| 마크 1분봉 | 2019-12-23 11:58 | 3,548,827 | 55분 |
| 지수 1분봉 | 2019-12-23 11:58 | 3,548,822 | 60분 |
| 확정 펀딩 | 2019-09-10 08:00 | 7,706 | 원천 조회 범위 완료 |
| archive OI 5분 | 2020-09-01 00:00 | 629,510 | 7,546개 라벨 누락; 격리 24일 포함 |

[ledger.json](ledger.json)에 월별 상태, 정확한 누락 구간, 격리 날짜, 연속 범위와 품질
표시를 기록했다. 펀딩의 완전성은 REST 조회 범위가 완료됐다는 의미이며 이벤트 존재를
고정 8시간 격자로 증명하지 않는다. archive OI와 REST OI는 합치지 않았다.

[공개 파일 목록](archive-availability.json)과 [REST 시작점 응답](rest-availability.json)을
직접 확인했다. 현물은 2019년부터 요청했고, 월별 선물 파일 이전의 2019년 구간은 REST로
수집했다. OI는 2020-09-01부터 2022-12-31까지 852개 일별 파일을 추가 조회했다.
장기 aggTrade 아카이브·과거 전체 호가·소비자 플랫폼으로의 추가 내보내기는 이번 범위 밖이다.

## 수집과 원천 예외

2020-01 시범 수집은 현물·선물 거래봉 각각 44,640행, 펀딩 93행을 확보했다. 마크·지수는
각각 29분이 원천에서 비어 있었고 REST에서도 확보하지 못했다. 이후 과거 확장과
보완 REST 조회로 **73,128행을 추가 복구**했다. 남은 누락은 값을 합성하지 않았다.

- `backfill-set`은 다운로드·정규화를 writer 밖에서 수행하고 UTC 하루씩 게시한다.
  시범 수집의 최대 단일 잠금은 0.0313초 미만, 전체 확장·복구에서는 0.1684초 미만이었다.
  이는 측정된 보유 시간이며 대기 시간이나 앞으로의 실행 상한은 아니다.
- 일부 현물 캔들의 원문 종료 시각은 명목 1분보다 짧았다. 파서 버전 2부터 실제 종료를
  보존하고 `short_source_bar`를 추가한다. 최종 활성 자료에 9개가 있다. 시간 격자 완전성과
  캔들 길이는 다른 검사다.
- 2020-12 현물 파일의 한 행은 종료가 시작보다 이른 잘못된 시각이었다. 이를 계속 거절하고
  해당 월을 REST에서 다시 확보했다. 따라서 최초·아카이브 재시도 보고서에는 실패가 남는다.
- 초기 OI 263일에는 모든 CSV 필드가 같은 중복이 있었다. 파서 버전 3으로 저장된 ZIP과
  CHECKSUM을 재검증·재처리했다. 첫 행을 표준 자료에 유지하고 중복 원문 번호·품질 표시를
  남겼다. 최종 활성 자료의 `exact_source_duplicate` 표시는 75,255행이다. 다른 필드의 값이
  다르면 계속 거절하며 원본 ZIP은 변경하지 않는다.

[복구 이력](backfill-and-repairs.json)과 [실제 원천 행 예시](source-anomalies.json)에
초기 실패와 보완 결과를 구분했다. 최종 확보 범위는 초기 실행 상태 대신 ledger를 기준으로 본다.
재실행 방법과 정책은 [확장 운영 문서](../../../docs/history-extension.md)에 있다.

## 실시간 수집과 depth의 한계

과거 확장 감시 구간은 UTC 14:05:32~14:42:06이다. aggTrade에 새 연결 오류나 미복구 ID 공백은
없었다. 실행 중 최신 저장 수신 시각의 최대 나이는 aggTrade 6.68초, depth 8.22초 미만이었다.
네트워크 도착 지연 측정은 아니다. depth의 동기화 실패는 실제 발생했고 숨기지 않았다.

1. 이전 호가 범위 소진 두 건을 원문으로 진단했다. 남은 매수 단계 265개·747개가 각각
   한 증분에서 사라졌다. REST 대조를 10초로 단축하고 조기 갱신 기준을 늘렸으며,
   범위 소진 시 같은 소켓에서 새 epoch를 시작하도록 했다.
2. 14:10 이후에는 원천 REST 스냅샷이 증분보다 뒤처지는 문제가 반복됐다. 14:32의
   100·500·1,000 단계 응답 모두 거래 시각 T가 수신 시각보다 약 127초 이전이었다.
   ID 연결 조건을 완화하지 않았다. [크기별 원문 진단](depth-limit-probe.json)
3. 14:22:54부터 새 정책을 배포해 같은 소켓에서 미복원 증분을 계속 저장하고 10초 간격으로
   새 기준 스냅샷을 시도했다. 이후 **14:41:52 시작 epoch에서 동기화가 회복**됐다.
   해당 수집의 지연 스냅샷 실패 111건과 미복원 구간은 그대로 남는다.
4. 첫 약 11분의 증분 5,720개는 `pu` 연결에 공백이 없고 모든 가격·수량이 원문과 같았다.
   [지연 중 보존 감사](depth-lag-audit.json). 회복 이후까지 확장한 감사에서는 12,335행과
   가격·수량 4,375,597쌍이 원문과 일치했다. REST 대조 18개 중 17개는 실시간에,
   나머지 1개는 저장 증분을 사용한 지연 대조로 확인했다.

확장 감사의 원문 ID 공백 1개는 15분 예정 연결 회전 경계에 있다. 과거 오류가 있는 전체
수집을 완전한 호가 이력으로 표시하지 않는다. `replay_matches_live=true`와
`raw_to_canonical_equal=true`이지만 `replay_valid=false`이며 감사 시 수집은 실행 중이었다.
이전 실패 수집 두 건도 새 코드로 다시 재생해 당시 결과와 일치했고 여전히 불완전이었다.
[스트림 증거](streams.json), [이전 범위 소진 진단](depth-coverage-summary.json).

## 무결성·백업·현재 운영 범위

- 전체 테스트 **210개**와 Ruff 검사·형식 검사 통과. [테스트](tests.xml), [코드 해시](validation.json)
- 등록된 파일 **51,365건** 검사에서 무결성 오류 0건. [검사](integrity.json)
- 기존 고정 구간의 활성 revision과 스냅샷의 전후 해시 일치. [보존 검사](preservation.json)
- 새 전체 백업 **2,771,656,372바이트**, 생성 후 검증 통과. [백업 결과](backup.json)

백업 위치는 `backups/history-extension-2026-09-23`이며 ID는
`0769125292492439a9d0852d9b56425414557479011364c79f516d6e49eec9cc`다.
기존 백업을 삭제하지 않았고, 같은 파일시스템의 사본이므로 외부 장치 백업은 아니다.
실시간 수집은 백업 시점 이후에도 계속된다.

운영 상태의 기존 4개 stale 항목은 2026-09-22 선물 거래봉·마크·지수·archive OI의
원천 일별 파일 미확보 상태다. 위 고정 검증 종료 경계 이후의 하루이며 과거 확장 누락과
구분한다. 현재 값은 `marketdata status --table`, `aggtrade-status`, `depth-status`로 확인한다.
[검증 당시 운영 상태](operational-status.json)를 전체 정상 판정으로 해석하지 않는다.
