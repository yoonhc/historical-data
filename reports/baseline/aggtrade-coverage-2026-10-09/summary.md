최초 시험부터 전체 기간이 채워진 것은 아니다. 상시 시작 전에는 별도로 4개 미수집 범위가 남아 있다.

## 로컬 대조 범위

행 수는 출처 간 중복을 제거한 고유 체결 수가 아니다. 관측 끝은 10/9 00:47:01.365 KST의 거래다.

정식 상시 서비스 시작은 [9/23 운영 전환 기록](../automation-2026-09-23/summary.md)의 **9/23 16:00:17 KST**다.

초기 4구간 합계는 1,901,391개 ID다. 당시 명시적 fresh-start 경계 3건과 그 이전 REST/WS 표본의 간격을 포함한다.
상시 서비스의 장애 4건이라는 의미는 아니다.

파일 내부 ID 폭과 행 수가 다른 segment는 9/25의 WS 사본 1개였다. 실제 Parquet을 읽어
`3465086434–3465086436` 3개가 빠졌고 REST 사본에 저장돼 있음을 확인했다. 합친 뒤 미복구 0이다.

## 공개 아카이브

[Binance 공식 안내](https://github.com/binance/binance-public-data#futures)는 선물 aggTrades의 일별·월별 파일,
일별 자료의 다음 날 제공과 checksum을 설명한다. [실제 HTTP 확인](archive-availability.json)에서는 다음을 확인했다.

| 객체 | 결과 |
|---|---|
| BTCUSDT 2026-09 월별 ZIP | 200, 437,374,990 bytes |
| BTCUSDT 2026-09-22 일별 ZIP | 200, 19,397,933 bytes |
| BTCUSDT 2026-10-07 일별 ZIP | 200, 14,953,649 bytes |
| BTCUSDT 2026-10-08 일별 ZIP | 404. 점검 시각에는 아직 UTC 10/8 진행 중 |

10/7 ZIP의 처음 64KiB만 Range GET(206)하여 CSV header를 확인했다.
`agg_trade_id,price,quantity,first_trade_id,last_trade_id,transact_time,is_buyer_maker` 7개 열이었다.
전체 ZIP·checksum 검증이나 결측 ID의 실제 파일 포함 여부까지 확인한 것은 아니다.

아카이브로 과거 체결 ID·가격·수량·거래 시각 등을 보강할 수 있다. 그러나 당시 이 PC의 WS 수신 시각과
WS 이벤트 시각은 이 파일에 없다. 확인한 파일은 `normal_quantity`도 없으므로 임의 추정하지 않는다.
자료를 나중에 받으면 실제 다운로드/수신 시각과 archive 출처를 기록하고 기존 WS·REST·partial 이력을 보존한다.

현재 aggTrade 아카이브 수집·등록 어댑터는 미구현이다. 기존 캔들/OI 아카이브 수집이 aggTrade까지 자동 보강하는 것은 아니다.
권장 후속은 최근 공백의 제한된 REST 보강과 별개로 일별 아카이브 수집·checksum/ID 대조·누락 보강을 연결하는 것이다.
REST 48시간이 지나면 영구 손실이라는 의미로 우선순위를 설명하지 않는다. 실제 파일의 공개와 내용 확인이 필요하다.

이번 작업은 조회·검증 기록 작성뿐이다. 수집 서비스·요청 예산·운영 설정·원본·백업·정리 승인은 변경하지 않았다.
