# 최근 이벤트 버퍼를 이용한 호가 복구 — 2026-09-26

같은 WebSocket 연결에서 이미 받은 최근 이벤트를 보존해 **뒤처진 검증 스냅샷 정렬**과
**범위 소진 후 새 anchor의 동기화**에 사용하는 기능을 구현했다. 엄격한 ID 연결,
검증 스냅샷의 상위 호가 일치 조건과 기존 실패 판정은 유지한다.

운영 적용에 앞서 별도 작업 사본에서 전체 테스트, 실제 과거 실패 자료, 별도 저장소의
실시간 수집을 검증했다. KST 12:38에 운영 적용을 완료했다.
[적용 파일과 해시](release.json), [검증 결과](validation.json)

## 정책과 호환성

- `history_policy=bounded_same_socket_v1`, `history_limits`를 새 수집에 기록한다.
  버퍼 한도는 **128개 이벤트 / 50,000개 가격·수량 쌍 / 정규화 직렬화 크기 8 MiB**다.
  어느 한도든 넘으면 오래된 이벤트부터 제거한다. Python 전체 메모리가 8 MiB라는 의미는 아니다.
- 뒤처진 검증 스냅샷은 당시 이미 받은 이벤트로 현재 업데이트 ID까지 진행시킨다.
  양쪽 상위 N호가가 충분하고 가격·수량이 정확히 같을 때만 가격 범위를 갱신한다.
  같은 ID의 불일치는 동기화 실패로 처리하며, 연결을 증명하지 못한 후보는 채택하지 않는다.
- 같은 소켓에서 범위 소진·지연 anchor 이후 새 epoch를 시작할 때만 버퍼를 이어받는다.
  소진을 유발한 이벤트와 지연 epoch의 미복원 이벤트도 보존한다. 새 연결·계획 회전·단절
  후 재연결에서는 버퍼를 비워 서로 다른 연결의 과거 이벤트를 이어 붙이지 않는다.
- anchor 정렬에 사용한 과거 이벤트를 새 epoch의 수신·적용 건수에 중복 합산하지 않는다.
  `anchor_history`, `checks[].history_alignment`에 별도 적용 근거를 남긴다.
  복구에 성공해도 이전 epoch의 오류·미복원 수량·`partial` 판정은 소급 수정하지 않는다.
- 수집과 재생이 같은 정책 선택 함수를 사용한다. 정책이 없는 과거 journal은 기존 규칙으로
  재생하며, 알 수 없는 정책이나 해당 버전과 다른 한도는 거부한다. 원문 검사도 새 정책의
  버퍼 한도를 넘어 추가 정렬한 결과로 당시 판정을 변경하지 않는다.

REST 주기·요청 한도·15분 연결 회전·시간별 세션·5초 flush·영구 보관·백업 설정은 변경하지
않았다. 현재 범위를 빠르게 벗어나 더 최신 스냅샷이 필요한 문제까지 해결한 것은 아니다.

## 테스트와 실제 과거 자료

전체 **256개 테스트**와 lint·format이 통과했다. 추가 테스트는 지연 스냅샷 일치·불일치의
실제 capture/replay, 불완전한 상위 호가, 세 가지 버퍼 한도와 단일 과대 이벤트,
ID 누락·충돌·역전, 소진 이벤트 보존, 지연 epoch의 미복원 업데이트, 새 연결의 버퍼 초기화,
과거 정책 호환성과 잘못된 정책 거부를 확인한다.

과거 완료 세션 3개의 **106,725행**을 새 재생기로 재생했고 당시 상태와 정확히 일치했다.
정상 세션은 정상으로, 부분 실패 세션 2개는 `valid=false`로 유지됐다.
[기존 기록 호환성](legacy-replays.json)

별도로 지난 두 점검에서 확인한 실패 epoch 6개의 **18,892행**을 원문과 대조하고,
동일한 입력에 새 코드를 적용했다. 이전 epoch의 최종 상태도 기존 정책으로 각각 재현했다.

‘실패율 4/6 감소’로 해석하지 않는다. 원본 카탈로그 보고서와 과거 실패 판정은 변경하지 않았다.

## 운영 적용과 후속 확인

호가 서비스만 SIGINT로 정상 종료해 버퍼를 보존한 뒤 검증한 파일을 적용하고 다시 시작했다.
설치·시작 검증이 실패하면 기존 파일로 되돌리는 절차를 준비했으며, 이번 적용은 정상 완료돼
되돌리기는 실행하지 않았다. 서비스 유닛·타이머·백업 설정은 변경하지 않았다.

- 새 수집 시작: **9/26 12:38:39.783 KST**,
  collection `015232156eb4415a926100df9d2199ce`.
- 직전 collection `cf579e6a510b4dd3ab1c2aa34b05cb1f`는 의도한 재시작으로 `interrupted`가
  됐고, 수신 8,618개와 보존 8,618개가 일치했다. 종료 이력은 남겼다.
- 첫 신규 수신과 직전 마지막 수신의 차이는 **2.549813초**다. 애플리케이션 관측 간격이며
  이 경계를 소급 복구했다는 의미가 아니다.
- 12:39:06 조회: 새 메시지 248개 보존, 동기화 실패·범위 소진·스냅샷 지연 0회,
  독립 대조 2회 일치. 호가·체결·유지보수 상태 모두 healthy였다.
- 설치된 파일 7개의 해시가 검증한 릴리스와 일치하고 호가 서비스 유닛 해시도 그대로다.
