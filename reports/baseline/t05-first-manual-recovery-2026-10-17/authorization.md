# 첫 수동 정리의 설치 형식 보완·같은 계획 재시도

사용자는 2026-10-17 **“오케이 첫 수동 정리 진행하자”**고 계획
`31766af4d1fec615372a7c7cb37c380e13f734a62b548986cd858c3e8937ba08`의 후보 10개를 승인했다.
16:15 시도 `4a61c943702c41bcb4b5e854ac098440`은 실제 사본 검사/시각 조회/삭제 전 유닛 링크 검사에서 보류됐다.
삭제 0개·journal 없음·수동 승인 비활성 복원과 모든 기존 사본/근거 보존을 확인했다.

제시하는 관리자 명령은 다음의 좁은 보완과 동일 계획 재시도를 수행한다.

- `/etc/systemd/system/marketdata-checkpoint-retirement-apply@.service`의 링크 하나를
  현재 승인된 원본과 같은 1,797바이트의 root:root/0644 일반 파일로 바꾼다.
  SHA-256은 `9932a3c4a8bc5acc74d5ba9c98d6348e2e367524999e15181b246fd0ac3addd0`으로 유지한다.
- system manager의 daemon-reload 후 UID 1000에서 설치된 실제 `installed_service()` 검사를 먼저 통과해야 한다.
  실패하면 업무를 시작하지 않고 원래 링크로 복원한다. Chrony/수집기 재시작이나 timer 활성화는 하지 않는다.
- 현재 scope·원래 계획·엔진 코드·정책·기존 근거는 유지한다. 이전 거부의 정확한 run ID와 해시,
  삭제/선정 미시작·journal 부재를 확인한 경우에만 같은 계획을 다시 시작한다.
  다른 실패, 삭제가 시작된 run, 새로운 journal은 거부한다. `resume_interrupted=false`를 유지한다.
- 설치 정리기의 모든 기존 검사 후 후보 10개만 처리하고, 종료 시 manual을 원래 비활성 바이트로 복원한다.

이 문서는 새 구현·보완 범위를 제시하는 기록이며, 사용자에게 제시하기 전에 이미 운영 보완을 적용했다고 주장하지 않는다.
실제 관리자 실행과 그 결과를 별도 receipt에 남긴다. 반복 자동화·부분 삭제 재개·새 계획·정책 변경 권한은 없다.
