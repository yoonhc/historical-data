# T19 검증 비용·기록 보관·용량 관리 설계 초안

T18의 장애 복구와 성공 manifest 본문 공유는 완료했다. 이 초안은 **남은 과거 출력·일반 로그·반복 조회 비용을 하나의 관리 범위로 묶는다.** 현재 배포본·timer·조회 빈도·T05 조건은 유지한다. 아래 정책은 아직 구현·운영 승인되지 않았다.

## 작은 적용 단위와 우선순위

1. **다음 공간 회수 묶음:** 종료된 과거 성공 출력의 경로/내용/권한/receipt를 유지하는 공유. [정확한 1,024개 읽기 전용 검토](review.md)를 먼저 사용한다. 전체 과거 136GB 분류나 새 플랫폼 구현을 기다리지 않는다.
2. **기록 분류·보관 예산·용량 경고:** 일반 진단과 필수 근거/미완료 참조를 분리하고 기간과 총량을 함께 제한하는 적용안을 만든다. 기존 기록을 이름이나 mtime만 보고 일괄 제거하지 않는다.
3. **조회 비용 분리:** 30분 새 사본 발견·보관·잠금 보류 재평가는 유지하면서 과거 manifest 전량 재대조를 일일/명시 감사 등으로 분리하는 후보를 검토한다. 실제 이상 발견 지연과 중단 복구 영향을 먼저 대조한다.

새 도구마다 별도의 대형 프로젝트를 만들지 않는다. T14는 기존 단계별 비용과 필요한 작은 I/O 계측을 제공하며, T16 보조 기록의 독립 복구는 이미 등록된 조건부 범위와 연결한다.

## 기록별 계약

| 종류 | 유지해야 할 연결 | 보관·용량 관리 방향 |
|---|---|---|
| 성공한 동일 manifest 본문 | repository·snapshot·경로·내용 해시와 실제 검증 receipt | 새 공유 방식 유지. 과거 독립 출력은 검증된 묶음만 공유. 본문을 참조하는 마지막 경로 제거 조건은 별도로 정의 |
| 실행별 작은 receipt | 명령 시작/종료·결과·실제 조회 여부·검증 해시·본문 참조 | 공유 stdout mtime 대신 receipt 시각 사용. 과거 결과 재사용 시 마지막 실제 검증 시각을 유지 |
| 일반 진단/진행 로그 | 필요한 최근 진단 범위 | 초기 검토안은 최근 7일과 총량 예산의 동시 적용. 예산 수치는 실제 분류량과 실패 출력 증가를 확인해 고정; 기간만으로 무제한 증가를 허용하지 않음 |
| 저장·전체 검사·복원·삭제 핵심 근거 | 해당 사본·복구·감사·T05의 참조 | 일반 로그 만료에서 제외. 필요 기간/참조 해소를 확인하거나 검증 가능한 보관 위치로 전환한 뒤 정리 |
| 미완료 요청·실패·시각 판정/JSONL | request/pins/attempt 및 정확한 파일 또는 byte 구간 | 참조가 해결되기 전 나이만으로 삭제/압축/절단하지 않음. 필요한 근거가 예산을 초과하면 경고와 보관/생성 작업 조치를 명시하며 조용히 버리지 않음 |

독립 백업에서의 request 복구는 아직 별도 후속이다. 보관 대상 목록을 정하는 것만으로 독립 복구 구현/시험까지 완료했다고 쓰지 않는다.

## 파일시스템별 공간 관리

`/home`과 `/mnt/backup`을 별도로 관찰한다. T05가 backup 파일시스템에서 공간을 회수해도 운영 `/home`의 수집 여유가 늘었다고 계산하지 않는다. 경고 입력은 일반 계정 실제 가용량, 기존 수집 보호 여유, 다음 작업의 최대 임시 출력, 관측된 자료/진단 증가량이다.

이번 관찰 기준 `/home`은 약 15.96GB이고 기존 보호 여유는 10GiB(10.737GB)다. 차이 약 5.22GB를 장기 용량 보장으로 취급하지 않는다. 다음 묶음의 예상 회수 8.61GB는 당장 여유를 늘리는 한 단계이며 장기 증가율 해결은 별개다.

일반 진단 영역은 기간+총량 예산을 넘기기 전에 감지하고, 비필수 반복 출력을 먼저 제어하는 계약을 정한다. 필수 근거 때문에 무제한 공간 사용을 허용하거나 수집 보호 기준을 낮추는 방법은 쓰지 않는다. 실제 경고 임계값·전달 경로·초과 시 동작은 적용 전에 고정하며, 이 문서로 알림 전송이나 서비스 중지 권한이 생기지 않는다.

## 반복 조회의 현재 비용과 후속 판단

10/25 자연 no-op 실측의 같은 30개 snapshot이 하루 48회 평가된다는 가정으로만 환산하면 다음과 같다.

| 항목 | 회차당 실측 | 하루 48회 단순 환산 |
|---|---:|---:|
| manifest 출력 논리 바이트 | 379,678,169 B | 18,224,552,112 B, 약 18.22GB |
| 큰 본문 추가 보존 할당 | 0 B | 관측된 동작 유지 시 0 B |
| 측정한 기타 파일 할당 | 290,816 B | 13,959,168 B, 약 13.96MB |
| 판정 JSONL 두 회 평균 | 8,220.5 B | 394,584 B, 약 0.39MB |

18.22GB는 실제 네트워크/물리 디스크 쓰기 계측값이 아니다. 기타 파일 값도 디렉터리 메타데이터·현재 request 교체 등 전체 비용을 포함하지 않는다. 성공 출력 공유 후에도 독립 임시 stdout의 쓰기와 해시 검증은 매번 수행된다.

조회 후보에서는 새 checkpoint·미보관/불명확 결과·repository 신원/존재 확인·복구 검증을 유지하고, 이미 확인된 과거 manifest의 전량 대조 시점만 분리한다. 새 timer를 반드시 추가하는 방식으로 고정하지 않으며 기존 일일 검증과 역할을 대조한다. 과거 검증을 재사용한 것을 방금 새로 조회한 것으로 기록하지 않는다. 신규 저장 후 manifest/T05 bundle 확인·기존 전체 읽기 검사·T05 적용 전 조건은 현재대로 유지한다.

## 다음 적용 검증에서 필요한 차이만 확인

정확한 다음 정리 묶음의 원래 경로/바이트/권한과 receipt 유지, 중단 후 완료/미완료 구분, 예상/실제 회수량을 확인한다. 일반 로그 만료 후보는 미완료 참조 보호·총량 초과 동작·하드링크 마지막 참조를 확인한다. 조회 후보는 신규 사본·불일치·중단 복구와 마지막 실제 검증 시각을 확인한다. 완료된 T18 배포·여섯 사본 편입·전체 복원이나 T13/T15/T16의 과거 전체 시험을 다시 선행 조건으로 삼지 않는다.
