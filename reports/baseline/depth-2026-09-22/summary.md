# BTCUSDT 선물 호가 depth 수집·재생 검증

2026-09-22에 BTCUSDT USD-M 선물의 100ms 증분과 REST 최대 1,000호가 스냅샷을 수집하고,
호가 복원·독립 스냅샷 대조·저장 자료 재생·백업 복원을 검증했다. 수집기는 Freqtrade에 의존하지
않으며 기존 캔들·OI·aggTrade 저장 자료와 같은 카탈로그·원문·불변 파일 체계를 사용한다.
[사용법과 정확한 범위](../../../docs/orderbook-depth.md)

## 실데이터 검증

시각은 UTC다. 먼저 35초 표본에서 업데이트 341건과 스냅샷 4개를 저장했다.
독립 REST 대조 3회가 일치했고 원문 가격·수량 쌍 73,284개의 표준 데이터 대응도 확인했다.
이후 연결 교체를 포함한 180초 표본을 검증했다.

[수집 이력](stream-pilot.json), [재생 결과](replay-pilot.json), [원문 대조](source-parity.json),
[세그먼트 목록](segments.json)에 수량·시각·원문 및 파일 식별자를 보존했다.

연결 교체 사이의 두 구간은 과거 REST로 복구할 수 없으므로 미수집 경계로 남겼다.
`valid=true`는 각 epoch의 재생 검증 결과이며, 여러 epoch를 이어 붙인 전체 구간은
`continuous=false`다. 35초 단일 연결 표본의 `continuous=true`도 관측한 이벤트 사이의
연결성을 뜻하며 수집 시간 양 끝이나 모든 시장 상황의 완전성을 증명하지 않는다.

최초 샌드박스 실행은 DNS 제한으로 연결하지 못했다. 데이터 0건의 실패 기록은 삭제하지 않고
[별도 기록](sandbox-failure.json)에 남겼다. 네트워크 접근이 허용된 실행에서 위 두 표본을
수집했다. [상태 기록](status.json)은 종료된 표본을 실행 중인 서비스로 표시하지 않는다.

## 저장량과 시각

180초 표본의 실제 파일 크기는 다음과 같다. 초기 동기화·검증 스냅샷을 포함하며,
앞선 35초 표본·SQLite·백업·복원본은 제외한다.

| 항목 | 파일 수 | 바이트 |
|---|---:|---:|
| WebSocket 원문 gzip | 35 | 1,392,972 |
| REST 스냅샷 JSON | 9 | 378,826 |
| 표준 Parquet | 44 | 2,744,697 |
| 합계 | 88 | 4,516,495 |

파일시스템 할당량은 4,698,112바이트다. 이 짧은 표본으로 하루 저장량을 확정하지 않는다.
[용량 보고서](capacity.json)

`received_at - timestamp`는 표본에서 약 -24.101~74.939ms였고, 1,720건 중 1,711건이 음수였다.
서로 다른 시계와 수신 큐가 관여하므로 이를 네트워크 지연으로 해석하지 않는다. 시계 오차의
원인을 검증하거나 원천·로컬 시각을 보정하지 않았으며 두 값을 그대로 보존했다. 시각 정렬을
이용한 지연·시점별 가용성 연구에는 별도 시계 검증이 필요하다.

## 자동 검사와 백업 복원

전체 테스트 162개가 통과했다. 새 depth 테스트 25개는 선물의 포함 경계 동기화, `pu` 연결,
절대 수량·삭제, 알려진 가격 범위, 중복·충돌, 누락·연결 단절 후 새 스냅샷, 원문 보존,
429 대기, Ctrl-C·강제 종료 후 재시작, 공간 부족, 원문과 독립 스냅샷 대조, 재생·백업·손상을
검사한다. Ruff 검사·포맷과 diff 공백 검사도 통과했다.
[검증 메타데이터·소스 해시](validation.json), [테스트 결과](tests.xml)

새 로컬 백업은 10,769개 파일, 875,471,355바이트다. 이벤트 세그먼트는 기존 aggTrade 56개와
두 depth 표본 55개를 합쳐 111개다. 카탈로그 고정 시 writer 잠금은 약 0.069초였다.
별도 경로로 복원한 뒤 두 depth 표본 2,074행·4개 epoch의 재생 결과가 원본과 일치했고,
기존 고정 스냅샷 20개의 manifest도 같았다. 복원본 등록 파일 무결성 10,748건이 통과했다.
이전 aggTrade 단계의 백업 10,639개 파일 검증도 통과했다.

- 백업: `backups/depth-pilot-2026-09-22`
- 복원본: `restore-checks/depth-pilot-2026-09-22`
- 백업 ID: `32a814e3394b350a1c895ed8cd78599897c5b42ab955676a1929068874e69769`
- 근거: [백업](backup.json), [복원](restore.json), [재생·manifest 대조](restored-check.json)

백업·복원본은 원본과 같은 파일시스템에 있다. 외부 백업이나 정기 예약을 추가하지 않았다.
기존 운영 대상 9개는 정상 상태였으며 기존 네 타이머와 Freqtrade 설정은 변경하지 않았다.

## 남은 범위

이번 표본은 종료했다. aggTrade·depth의 상시 서비스나 장시간 안정성 검증은 아직 수행하지 않았다.
현재 depth 명령은 최대 1시간 수집·수집 ID별 최대 100,000행 재생을 제공한다. 단절 사이
과거 호가 복구, 전체 가격 범위의 완전한 호가장, RPI 주문, 현물 depth, 고정 스냅샷 API와
Freqtrade 호가 어댑터는 이번 구현 범위가 아니다.

Git에는 검증 보고서와 코드만 남긴다. 원문·Parquet·SQLite·전체 백업 manifest는 로컬에 보존한다.
