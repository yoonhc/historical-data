# 2026-09-23 상시 수집·자동 유지보수 전환

BTCUSDT USD-M aggTrade·depth를 1시간 세션을 반복하는 사용자 systemd 서비스로 전환했다.
매시간 종료 자료를 묶고, 매일 전체 검증·백업을 수행한다. 원문·표준 데이터·수집 이력은
기간 제한 없이 보존하며, 검증된 개별 중복 사본 외에는 자동 삭제하지 않는다.
이 문서는 전환 당시의 기록이다. 최신 운영 상태는 [운영 명령](../../../docs/stream-services.md)으로 확인한다.

## 실제 서비스 전환

UTC **2026-09-23 07:00:17 / 한국 시각 16:00:17**부터 다음 구성이 활성화됐다.

| 구성 | 설정 |
|---|---|
| aggTrade 서비스 | 3,600초 세션, 마지막 저장 ID 재개, 세션 사이 REST 복구 |
| depth 서비스 | 3,600초 세션, 900초 연결 회전, 30초 top 20 대조 |
| 두 스트림 공통 | 5초 flush, 종료 후 15초 재시작, SIGINT 종료·최대 120초 대기 |
| pack 타이머 | 매시 UTC 15분 및 활성화 5분 후, 종료 후 1시간 지난 수집만 대상 |
| backup 타이머 | 매일 UTC 04:10 / 한국 시각 13:10, 전체 검증 후 백업 |
| 유지보수 충돌·실패 | 전용 잠금 직렬화, 120초 후 재시도, 1시간 최대 4회 |

두 서비스·새 타이머 두 개는 enabled/active다. 기존 네 타이머도 유지한다.
[활성화 시점 systemd 설정](systemd-at-activation.txt), [실행 단계](activation.json)

WebSocket 429/418 대기 시간을 파일에 보존해 다음 프로세스도 접속을 제한하도록 추가했다.
최소 5분/1시간과 더 긴 `Retry-After`를 따른다. 유지보수는 종료 자료만 대상으로 삼으며
새 묶음과 중단 후 남은 사본만 검증·정리한다. 이미 정리한 전체 과거 묶음의 해시를 매시간
다시 계산하지 않는다. 묶음별 카탈로그 조회에는 `packed_files(pack_id)` 인덱스를 추가했다.

## 기존 운영 상태와 한계

REST OI·OI 관측기는 계속 수집 중이다. 일반 운영 상태 전체는 `healthy=false`를 유지한다.
9월 22일 선물 거래봉·마크가격·지수가격·archive OI 파일의 HTTP 404가 기존 daily 실행과
이번 재조회에서도 발생하여 원천 대기 상태이기 때문이다. 이 네 범위는 이번 스트림 자동화
이전에 이미 누락으로 표시돼 있었다. archive OI를 REST OI로 치환하지 않았다.
[전환 전](operations-before.json), [재조회](daily-retry.json), [전환 후](operations-status.json)

다른 다섯 운영 데이터셋은 정상이며, 새 유지보수의 파일 무결성 통과는 원천 자료의 기간
완전성과 구분한다. 오래된 과거 표본의 오류 이력도 계속 보존한다.

전체 **199개 테스트**가 통과했다. 추가 14개 검사는 유지보수 직렬화·멱등성, 중단된 정리와
백업 재개, 손상 시 백업 중단, 부족한 용량, 오래된 상태, 잘못된 대상, 재시작 후 WebSocket
cooldown 및 Retry-After 연장을 검증한다. Ruff·포맷·diff 공백 검사와 systemd 유닛 검증도
통과했다. [테스트 결과](tests.xml), [소스와 근거 해시](validation.json)
