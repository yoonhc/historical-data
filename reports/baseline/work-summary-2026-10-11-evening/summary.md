마지막 커밋 `bf630cc` 이후 T05 구현·검증·실제 설치, T04 복원 시험 공간 정리,
T13 실제 처리·정오 백업 점검과 고정한 남은 완료 범위를 보존한다.
[새 마일스톤](../../../docs/milestones/2026-10-11-checkpoint-evidence-and-daily-processing.md)은
이전 마일스톤의 01:04 KST 이후 작업 전체를 기준으로 작성했다.
정리한 시각을 운영 관측 시각으로 사용하지 않는다.

## 보존과 검토

두 T05 source archive·patch·manifest, 검사 XML/압축 로그,
실제 설치기·중단/원복/재개 코드와 원래 실패/최종 receipt를 함께 보존한다.
최종 151개 소스의 로컬 work/reproduced 사본이 archive와 일치함을 대조했고 중복 사본은 Git에서 제외했다.
운영 workspace 패키지를 후보 소스로 덮어쓰지 않는다.

T04의 최종 삭제 목록·journal·backup/restore manifest는 원본 해시를 확인해 baseline의 evidence 경로로 복사했다.
시장의 원문 데이터나 복원된 SQLite를 커밋하지 않으며, 원래 로컬 근거도 유지한다.
T13은 원장 압축 기록·실제 파일 대조·journal과 고정한 작업/시도 ID·완료 근거를 보존한다.

[파일별 해시](preserved-inputs.json)와 [보존 전 검사](commit-review.json)를 남긴다.
읽기 전용 검토는 archive 내 전체 소스/해시·patch·설치 입력·재개/receipt·T04 실행 근거·T13 대상,
Python 문법·JSON/JSONL/XML/gzip 무결성·로컬 문서 연결을 대조한다.
기존 T05 108개/최종 215개/58개 재현·전환 보완 16개·T04 연결 3개 결과는 과거 실행의 근거이며 이번에 다시 실행하지 않는다.
제한된 credential 패턴 검사는 모든 비밀값 부재를 보장하지 않는다. 비밀값 파일·venv·캐시·DB는 보존 대상에서 제외한다.
원본 patch 문맥이나 압축 시험 출력의 bytes를 공백 정리로 바꾸지 않는다.

설계 문서는 설치 후 진행 상황을 포함해 17:29에 갱신된 현재 문서이며 SHA-256은
`855276ffe56659cbbf6b3197398004cb8f99e5489c75e5a8cda8b413ebaac0ba`다.
후보 manifest의 당시 설계 해시 `06c3b92d9241610a34a890075bd0117fa9d7ec848f9a0a5c6e067fefc855ce1b`와
동일한 bytes로 취급하지 않는다. 당시 설계 원본의 별도 사본은 이번에 대조하지 못했으며 차이를 문구 수정만으로 단정하지 않는다.
고정 소스·patch·설치 승인 입력과 그 해시는 모두 별도로 대조하고 원래 manifest를 수정하지 않는다.

최종 입력 대조는 **178개 파일·18,497,675바이트**다. 두 archive의 144개/151개 소스와 로컬 사본,
배포 입력/재개/receipt 45개 해시 연결, T04 최종 목록/journal, T13 고정 대상이 일치했다.
고유 Python 135개 문법, JSON 78개·JSONL 8개(225,673행)·XML 15개·gzip 20개와 문서 연결을 확인했다.
최종 검사에서 누락 링크나 credential 패턴 일치는 없으며, 위 당시 설계 원본 미대조는 별도 한계로 남긴다.
[Git 인덱스 대조](staged-review.json)에서도 입력 178개의 bytes가 일치했다.
공백 경고 53개는 두 원본 patch의 문맥/빈 줄에 한정되며 고정 patch 해시를 유지하기 위해 수정하지 않았다.
그 외 스테이징 파일의 공백 검사는 통과했다. 이 결과 파일 자체를 추가하기 전 스테이징 수는 182개다.
